## [0.45.767] — 2026-11-11 — Fixed：v0.45.765 二次检查的两处修复（Bear 回落漏接 OSError 会丢整只票；Alpha Bot 深度页认不出弃权的 Oracle）

**起因**：用户 11-11 要求「二次检查以上更新有没有 bug」。检查分两路：我自己逐个查下游读者；另派一个独立审查代理只看 diff。审查代理用旧 / 新两版 oracle_bee 对拍复现。

### Fixed
- **`swarm_agents/bear_bee.py`：Bear 自己取期权链（回落分支）的 except 元组补上 `OSError`**，与 Oracle 取同一个 OptionsAgent 时用的元组一致。
  - 765 前：OptionsAgent 抛异常时，Oracle 吞下、照样上板，Bear 读板，不走回落。
  - 765 起：Oracle 吞下后弃权、不上板 ⇒ Bear 必走回落、多半撞上同一个异常。
  - `URLError`、`SSLError`、socket 超时都是 `OSError` 的子类，不是 `ConnectionError`。它们会从回落分支漏出去；`Bear.analyze` 的 `AGENT_ERRORS` 和扫描的逐蜂 except 也都不接 ⇒ 整只票这一轮丢掉，靠重试重跑全部蜂。
  - 复现：同一个抛 `URLError` 的 OptionsAgent 桩，旧代码 Bear 正常，新代码 Bear 抛 `URLError`。
  - 生产尚未发生：全部 2721 份归档记录（`.swarm_results_*.json`，只读）里 Oracle 记 `fallback`（OptionsAgent 抛异常）0 行、Oracle 出错 0 行。09-24 / 09-25 全网直连失败那两天，异常在 `_try_cboe` 里就被吞了、走样本链早退，没抛到 OptionsAgent 外面。
  - **作废 0 条，不登世代边界**：只在旧代码会漏出异常、整只票没有行的情形下改变行为；旧代码产出过的行，新代码逐位不变。
- **`swarm_agents/oracle_bee.py`：弃权结果的 discovery 改以 `Error: ` 开头**，同 `utils.make_error_result`。
  - Alpha Bot 深度页（`alphabot/deep_report._failed`）只按「发现以 Error / ❌ 开头」认出错的蜂：老记录没有 `error` 键，所以它不读那个键。
  - 765 原文不带前缀 ⇒ 期权链取不到那天，深度页把 Oracle 数成一张中性票（扫描本身没数它），也不标「出错」。
  - 结尾的 `| $价` 保留：网站缺 Scout 价时，从 Oracle discovery 里抠 `$数字`（`dashboard_renderer` 价格回退 1）。
  - discovery 不进评分（弃权不上板、不调 LLM），不影响任何分数。

### 核过、没改的（另议）
- 765 碎片「未改（另议）」只写了出错蜂的 5.0 进 `signal_archive`，**漏了方向**：
  - 蜂后的 `agent_directions` 从全体结果（含 error）建，弃权的 Oracle 记成 `"neutral"`。
  - 下游有三处：ML 特征 `agent_agreement`、`predictions.agent_directions`（逐蜂准确率诊断）、归档信号 `composite.swarm_agreement`。
  - 这是全体出错蜂的存量约定，**不在本版改**：
    - `agent_agreement` 训练端历史行也是这个口径，只改服务端会造出 train/serve skew。
    - `composite.swarm_agreement` 已在 765 的作用域闭包里，起点 11-09，不会跨口径池化。
    - `final_score` 干净（经真实蜂后：弃权与「Oracle 根本不在」逐位相同）。
- 期权链整天取不到时，Bear 会自己多取一次链：样本链结果不进快照缓存，每只票的失败取数多做一遍。耗时增量**待验证**：
  - DNS / TLS 当场失败：CBOE 重试的退避只有约 2 秒。
  - 连接挂起到超时：每只票最坏约 47 秒（3 次 × 15 秒 + 退避），CBOE 信号量串行。
  - 09-24 / 09-25 那类全网故障日属前一种。
- 网站「蜂群分歧度」把出错蜂的 5.0 / 中性也算进去：存量展示行为，与上面同属「出错蜂的占位值流进不看 error 的读者」。
