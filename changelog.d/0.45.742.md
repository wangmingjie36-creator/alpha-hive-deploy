## [0.45.742] — 2026-11-06 — Changed：接货型卖 put 账本选合约规则 v2——30~50 天窗口、IV/RV30 ≥ 1 门槛、按「年化 × IV/RV」综合分选合约与排序（用户定）
<!-- 认领：worktree-wheel-composite-score 2026-11-06T11:23:56-07:00 2510cee9 -->

**起因**：用户 11-06 问 NVDA 160P / XOM 140P 是怎么选的，随后定：「选择价格要满足隐含波动率高的行权价和日期」「年化也要考虑进去，要综合评价」「候选窗口为 30-50 天」。
用今天的链实测给用户看过：照字面挑「IV 最高」会固定挑最近、跨财报的到期日与最深虚值档（期限结构 + 偏斜，不一定是贵）；
同一只里各档 IV/RV 差很少，综合分多半由年化决定。用户选了「门槛 IV/RV ≥ 1 + 综合分 = 年化 × IV/RV」，窗口 30~50 天。
公式与门槛是主观设定、未经检验；之前一个月的数据里「溢价高 ⇒ 更赚」没有证据（预注册 §2.2 写明）。

### Changed
- `sell_put_wheel.py`
  - `CONFIG`：`put_dte_range` (55, 90) → **(30, 50)**，删 `put_dte_target`（不再取离目标最近的到期日）；新增 `rv_window = 30`、`min_iv_rv = 1.0`；`rank_by` = `annual_yield_x_iv_rv`。`_VERSION` → 0.45.742。
  - `pick_put(..., rv_pct=None)`：候选 = 窗口内**所有**到期日 × 不高于接货价的合格档，要有 IV、IV÷RV ≥ 门槛；取综合分最高（圆整 1e-9 后同分取更晚到期、再取更高行权价，与输入顺序无关）。新原因码 `no_rv` / `no_iv` / `iv_below_rv`；结构性原因（`no_expiry` / `no_strike`）先于 `no_rv` 报。
  - 新纯函数 `rv_from_closes`（≤ as_of 的最后 31 根，公式复用 `vrp_signal.realized_vol_from_closes`）、`score_put`；取数 `_default_rv`（`yf_daily` 新 source `sell_put_rv`，分红复权，截到 min(as_of, 最近已收盘交易日)）。`run_for_date` 加 `rv_fn` 注入口；只对要开 put 的标的取 RV。
  - 多只同时能开时按综合分排（原按年化）。`put_sold` 事件与持仓 put 腿新增 `iv_pct` / `rv_pct` / `iv_rv` / `score` / `rule_version`（缺 = v1）。
  - 失败可见：`stats()` 新增 `rv_total` / `rv_missing` / `all_rv_missing`；单只取不到 ⇒ skipped `no_rv` + 明细；整批取不到 ⇒ `alert_manager._check_sell_put` P2。
