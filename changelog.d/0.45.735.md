## [0.45.735] — 2026-11-05 — Fixed：补跑闸读不到钟时改为不扫描（此前空读数让 `[ -lt ]` 报错、条件为假而照跑）
<!-- 认领：worktree-restart-banner-paper-cooldown 2026-11-05T12:45:53-07:00 e1fbcf09 -->

**起因**：v0.45.731 在「注意到、没改」里记了一条：补跑闸两次读钟都读不出 `NOW_HHMM` 时（`date` 坏了 / 找不到，或 PATH 上的 date 不认 BSD 的 `-v`），`[ "" -lt 1630 ]` 报 `integer expression expected`、返回 2 ⇒ `if` 判假 ⇒ **照常往下扫描**。
- 本闸拦的正是盘中跑（盘中价写成收盘价是已知的头号样本污染源）。判不了几点，就判不了收没收盘。
- 用户选了「判不了就不扫」：漏一轮比污染样本好，定时点 / 下次开机会再试。

### Fixed
- `scripts/alpha-hive-orchestrator.sh` 补跑闸：在 UTC−5 兜底**之后**、`[ -lt ]` 比较之前加一道校验，只认合法的 HHMM（`0000`–`2359`）。
  - 不是合法 HHMM ⇒ 两行 `ERROR`（原样写出读到的值、给出排查命令）⇒ `_early_fail_status "failed_clock_unreadable"` ⇒ `exit 1`。
  - 校验必须查兜底之后的值：最像真事故的组合是时区数据坏了（第一读静默给 UTC 墙钟，四位数字、看着正常）+ 兜底那行读不出。校验放在兜底之前，验过的是被丢掉的第一读，空串照样放行。

### 为什么这么修
- **归「闸前失败」一族（`failed_*` + `exit 1`），不归 `skipped_*` + `exit 0`**：钟坏了是环境故障，不是正常跳过。标成 skipped 就是把一种失败报成了另一种。与 v0.45.432 代码目录那几条（`failed_project_dir_missing` 等）同一处理。
- **只认合法 HHMM，不只认「四位数字」或「是整数」**：`2400`、`1660` 能被 `[ -lt ]` 比，但比出来没有意义（会放行）；`930`、` 1700` 说明读钟的格式已经不对。`date +%H%M` 正常时恒为合法 HHMM，所以正常日子不会误拦。
- launchd plist 没有 `KeepAlive`：`exit 1` 不会触发重启循环（闸前另外几条早就是 `exit 1`）。

### 谁会红（读不到钟那天）
- 编排器日志里两行 `ERROR`；`~/.claude/reports/status.json` 为 `failed_clock_unreadable`；launchd 记下退出码 1。
- 不推送任何通知（同闸前另外几条；Slack 规则也禁止扫描失败 DM）。alert_manager 在 Step 6 才跑，这一轮走不到。持续读不到 ⇒ 当天无扫描，扫描连续性会显出缺口。

### 测试（`tests/test_scan_catchup.py`）
- `test_gate_exits_zero_not_error` 改写：原来断言闸段里根本没有 `exit 1`。现在逐个 `exit` 配它前面最近落盘的 status：`skipped_*` 必须配 `exit 0`、`failed_*` 必须配 `exit 1`，三个分支一个不多、一个不少。
- 新增 `TestGateUnreadableClock`（默认套件，CI 上也跑）：逐字取出编排器从读钟到时间闸判完的整段，带编排器原样的 `set -uo pipefail` 与 `_early_fail_status`，只换 `date`。
  - 8 种坏读数（空串、`abc`、`930`、`16:30`、`2400`、`1660`、`12345`、` 1700`）：都必须 `exit 1` + `failed_clock_unreadable`、不放行，且 ERROR 里原样写出读到的值。
  - `date` 整个坏掉：先 WARN 退到兜底，兜底也读不出 ⇒ 拦下。
  - 时区坏 + 兜底读不出（上面那个最像真事故的组合）。
  - 对照：合法读数照旧按阈值判（`0000`、`0905` 前导零、阈值前一分钟、阈值本身、`2359`），防「闸把一切都拦了」也能让上面全绿。
- 新增 `TestGateBranchesLive::test_unreadable_clock_fails_closed`（integration）：沙箱里真跑整个编排器，假 `date` 放在 PATH 最前，只让闸的三种调用失败。
