## [0.45.789] — 2026-11-20 — 跨式账本：0.45.787 的 bid=0 放宽限定为「未到期」（到期当天仍走到期内在价值结算，不再按 ask 平）

### Fixed
- `options_paper_leg.py`：0.45.787 的 `_exit_executable` 没限定未到期。到期当天（`to_expiry ≤ 0`）short 一条腿 bid=0 但有 ask 时，也会按 ask 平仓、绕过原本的到期内在价值结算。二次检查用探针对照（short K=100，看涨腿 bid=0 / ask=0.05，看跌腿 7.9 / 8.1，到期日收盘 92）：

  | 时点 | 0.45.787 之前 | 0.45.787 | 0.45.789 |
  |---|---|---|---|
  | 到期前一天 | 等待 | 按 ask 平 8.15 | 按 ask 平 8.15 |
  | 到期当天、有定稿收盘 | 内在价值 8.0 | 按 ask 平 8.15 | 内在价值 8.0 |
  | 到期当晚、无定稿收盘 | 延期一天再按内在价值 | 当晚按 ask 平 | 延期一天（设计内） |

  - v0.45.449 留下的缺口是「**未到期**取不到报价一律等」；到期当天设计本来就有答案（到期那一场的收盘算内在价值 = 合约真实结算价）。放宽到到期当天是改口径、不是补缺口：对一条没价值的腿再付一次 ask，并把当晚无定稿收盘的「延期一天」变成当晚就平。
  - 修法：`_exit_executable(..., allow_bid0=...)`，调用处传 `allow_bid0=not (to_expiry is not None and to_expiry <= 0)`；`allow_bid0=False` 退回两腿都须 `quote_ok`。到期日无法解析（`to_expiry` 为 None）与既有 `expired` 一致，视为未到期。其余（ask 判据、long 不动、`_quote_ok` 不动、`exit_bid0_legs`、`exit_blocked` 观测点）都不变。
- **更正 0.45.787 碎片里「NVDA 11-20 会走内在价值结算」的措辞**：在 0.45.787 的实现下并不成立——只要 NVDA 看涨腿当天有 ask，就会按 ask 平。0.45.789 起（11-20 的扫描前进了 main 的话）才是内在价值结算；NVDA 看涨腿 ask 是否 > 0 仍未取到，待验证。0.45.787 的碎片是已入 main 的历史记录，本版不改它。

### 没做的事（刻意）
- **没有统一到期当天的口径**：两腿都有正常双边报价时，到期当天本来就按报价（ask）平、不走内在价值，这是存量行为，本版不动（统一成「到期当天一律内在价值」会改已登记样本的出场口径，需用户另定）。
- 仍没接 P2 告警；仍没改影子宽跨协议文件。
