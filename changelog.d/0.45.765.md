## [0.45.765] — 2026-11-11 — Changed：Oracle 取不到数据时不再拿兜底 5.0 进分（异常流兜底不混入；期权链整条取不到 ⇒ odds 维缺席）
<!-- 认领：claude/oracle-no-fake-score 2026-11-11T11:29:50-07:00 bf7b06fc -->

**起因**：用户 11-11「我不想要假评分会污染综合评分」，选「两条都改」，按「作废 0 条」并进 11-09 世代起点。

**两处假分**：
- **① 异常流兜底**。`unusual_options.detect_unusual_flow` 取不到时返回 `data_source: "fallback"` 的兜底 dict，其中 `unusual_score` 恒为 5.0。这几种情况都算：全部到期日失败、OI 陈旧、无到期日、无现价、内部异常。
  - Oracle 按 0.10 / 0.65 把这个 5.0 混进融合分，相当于把 Oracle 分往 5 拉了 10/65 ≈ 15.4% 的距离。
  - 检测器自己抛异常时 flow 为空，只用期权分。同为「没取到」，两条路分数却不同。
- **② 期权链整条取不到**（样本链早退 / OptionsAgent 抛异常）。`options_score` 停在 5.0，再混入异常流，就成了一个由兜底常量撑起来的 odds 分进综合分，方向票也照投。

**生产实测**（10-07 ~ 11-10，25 个扫描日 750 行，只读）：
- ① 94 行，10-14 / 10-26 两天各 30 行占大头。融合分 |Δ| 中位 0.24、最大 0.51；按分数带算方向翻 6 行（未计 skew / LLM）。
- ② 2 行（10-14、10-26）。
- Oracle 出错 0 行。
- **11-09 起 60 行里 ① ② 都是 0 行**，所以作废 0 条。
