## [0.45.739] — 2026-11-05 — Changed：版本号一律补丁位、升 minor 先问用户；status 跳号按 minor 系列分别算（v0.45.733 复查第 3 条，用户定 B）
<!-- 认领：claude/clever-chatelet-396260 2026-11-05T14:15:28-07:00 c53514c6 -->

**起因**：v0.45.733 复查第 3 条「`claim` 升不了 minor」。往下查，根因不在工具：
- 规则「patch = bug fix；minor = 新功能批次」最早出现在 2026-03-16 的 CLAUDE.md。2026-08-27 起的占号规则要求开工先取下一个号，占位模板写死 `## [0.45.NN]`。两条规则矛盾了两个多月，实际执行的一直是后者。
- 0.45.0（08-16）之后补丁位一路走到 737，minor 一次没升；0.45.x 里标题以 Added 开头的就有 80 条。claim 工具（0.45.728）出现之前号是手写的，写 0.46.0 毫无阻碍，也没人写——工具不是原因。
- minor 规则在工作流里没有执行时机：号在开工时就占，那时还不知道这次算不算新功能批次；一个「批次」又横跨许多会话，没人负责宣布它开始。

用户看过 A（给 `claim` 加 `--minor`）/ B（改规则并修 status）的分析后定 B。

### Changed
- `.claude/rules/session-closing.md`「版本历史规则」：版本号一律由 `claim` 取（补丁位 +1），只当顺序编号；改动性质看标题里的 Added / Changed / Fixed / Removed。要升 minor 先问用户，定了再给 `claim` 加 `--minor`。原文与改的理由写在该行括注里。
- `changelog.d/README.md`「开工：占号」：加同一条速查。

### Fixed
- `changelog_fragments.py::status` 的跳号那一行（抽成新函数 `skipped_versions`）：
  - 原来只按档案所在的系列（0.45）算：`if lo[:2] == hi[:2] else []`。碎片一跨到 0.46，整段不查，却照样打印「跳号：无」——把「没查」报成「没问题」。0.45.728 写的，还没出现过 0.46，所以没触发过。
  - 改为按 minor 系列分别算：档案所在系列从冻结最大号 +1 查起，之后的新系列从 `.0` 查起，各查到本系列最大的碎片号。比档案系列还低的碎片不在冻结后的范围里（lint 已判红）。
  - 模块 docstring 的判据段注明「跳号按 minor 系列分别算」。
- 升到 0.46.0 时其余环节不受影响（已核对）：解析版本号的正则是通用的、按数值比较，之后接着取 0.46.1；代码里写死的 `"0.45.xxx"` 是各模块自己的版本戳与档案冻结值，不参与解析。
