## [0.45.808] — 2026-11-23 — Alpha Bot 对话抽屉：对话落盘保存、历史列表、手动归档（像 Claude Code）
<!-- 认领：feat/alphabot-chat-history 2026-11-23T10:34:09-07:00 e8cce592 -->

用户 2026-11-23 定：「对话里面可以保留历史对话吗，不要的我会自己归档，像 Claude Code 一样」。此前对话只在 Alpha Bot 进程内存里（最多 20 场、重启即丢），抽屉也没有历史列表。

### Added
- `alphabot/chat.py`：每场对话落盘到 Alpha Bot 状态目录 `chat/conversations/<id>.json`（`ledger_io.write_json`），存给 API 的原始历史 `messages`（原样，思考块照旧可放回）与抽屉显示用的 `display`（每问的用户原话 + 那一问的结果），每问答完写一次；`list_conversations(archived)` / `get_conversation` / `set_archived`。**没有自动清理、没有删除**：归档只是从列表藏起来，可随时取消归档，再问一句自动取消归档。内存 `_convs` 降为缓存（`MAX_CACHED_CONVERSATIONS`，挤出去的下次从盘读回；正在答的、没存上盘的不挤）；列表摘要按 mtime + 大小缓存。
- `alphabot/server.py`：`GET /api/chat/conversations`（`?archived=1` 看已归档）、`GET` / `POST /api/chat/conversations/{cid}`（POST 只收 `{"archived": true|false}`，照旧要 `X-AlphaBot` 头）。只读本机文件、不调 API。
- `alphabot/static/chat.js` + `alphabot.css`：抽屉顶栏加「历史」——列表（标题 = 第一问前 40 字、更新时间、问数）、点开接着聊、「归档」/「已归档（N）」/「取消归档」；再打开抽屉时接着上次那场（id 记在 localStorage，读写包 try，取不到就从新对话开始）；发送中「新对话」和打开别的对话都不可用（否则回答会进错的那场）。
- `tests/test_alphabot_chat.py::TestHistoryPersists`（9 条）+ `TestServer::test_history_endpoints` + `TestDrawer::test_history_view_is_wired`：跨「重启」（新引擎）原样放回历史、列表 / 归档 / 取消归档落盘、问归档的对话自动取消归档、缓存挤出后列表与历史仍在、失败的一问不进显示、坏记录文件报 `ChatHistoryUnreadable` 且不发请求 / 列表里标 error 不跳过、怪 id（路径穿越等）不拼路径、存盘失败照常交回答并注明、没有 DELETE。

### Changed
- 「谁会红」：存盘失败 ⇒ 回答照常交出、提示「这场对话没存上」，列表标「没存上盘」；记录文件坏了 ⇒ 不再当「没有这场对话」悄悄开新的，报 503 说清楚、不发请求、不计费。找不到对话时的提示改为「原对话找不到了（记录文件不在）」。
- `alphabot/static/pages/help.js`「对话」节：删掉「只存在内存、关掉就没了」，改写存储位置、历史 / 归档用法，以及隔很久再接着问首问要重写缓存、比连着问贵一些。

### 未验证
- 没真调 API（测试与浏览器实测都用假客户端）。隔天接旧对话时思考块放回能否被接受，按 v0.45.635 冒烟的结论应当可以（同一模型、历史原样），但跨天 / 跨进程这一种没真测过。
- 进生产要等扫描日生产克隆快进 + 重启 Alpha Bot。

### Fixed（808 二次检查，四处）
- ⭐`alphabot/chat.py::_trim_cache`：缓存满时从盘读回的旧对话 `updated` 最旧，会被同一次修剪**当场挤掉**——接着问照常答，但 busy 闸失效、答完存盘找不到它（「缓存里没有这场对话」），**这一问没存上**。现在刚放进来要用的那场（`keep`）不挤。第一版测试没抓到：测试钟钉死、大家 `updated` 相同，修剪按插入顺序挤、碰巧挤不到——改成会走的钟后旧代码即红。
- 答题期间点了归档，答完存盘又被自动取消归档 ⇒ 加 `archive_rev`：答题期间人改过归档就听人的。
- 合法 JSON 但字段类型不对（`created` 不是数、`display` 里有非对象）曾让整个历史列表抛 ValueError / AttributeError ⇒ 同样算坏记录：列表里标 error、打开报 `ChatHistoryUnreadable`。
- `alphabot/static/chat.js`：发送中不许归档正在答的那场（会清空视图、回答落进空白里）；打开对话 / 恢复上次对话取回后核对是否已过时（异步恢复曾可能盖掉正在发的那问）；历史列表只认最后一次请求的回复。浏览器里用慢回答的假客户端实测：答题期间该场「归档」与各「打开」都不可点，答完回答落在正确的对话里。
- 测试：`test_archiving_during_an_answer_sticks`、`test_wrong_field_types_are_a_bad_record_not_a_crash`（3 例）、淘汰测试改用会走的钟并核对存盘；前端结构守卫补三条。四处均用修复前代码跑过、确认会红。
