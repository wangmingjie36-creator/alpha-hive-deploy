## [0.45.738] — 2026-11-05 — Added：pre-push 加根目录 CLAUDE.md 预算闸（`changelog_guard.py`）：推往 main 且被推区间动了根目录 CLAUDE.md 或预算模块时，拿被推提交里那份比被推提交里写的预算，超了就拦并打印搬家步骤；预算与失败信息挪进共享模块 `claude_md_budget.py`

### Added
- `claude_md_budget.py`（新，仓库根）：
  - `ROOT_BUDGET_BYTES`、`section_sizes`、`over_budget_message` 从 `tests/test_claude_md_partitions.py` 挪来。逻辑不变，只把失败信息里「调大预算」的位置指明为 `claude_md_budget.py`。
  - 新增 `BUDGET_LINE` / `budget_in_source`：从某个版本的源码里读预算；读不出、或不止一处 ⇒ None。
- `changelog_guard.py` pre-push 新增根目录预算闸：
  - 被推区间动了根目录 `CLAUDE.md` 或 `claude_md_budget.py`（判据的两个输入；后一个是二次核对补的）才查，算不出区间按「动了」处理。两样都没动的推送不查，哪怕 main 上已经超了：例行拦无关推送会把人养成 `--no-verify` 的习惯。
  - 读被推提交里的 `CLAUDE.md`（按字节），比被推提交里 `claude_md_budget.py` 写的预算：按 `BUDGET_LINE` 读源码，不 import 被推的版本，所以工作区里没提交的调预算不算数。
  - 超了 ⇒ 拦，打印与测试同一段失败信息，再加一句「别用 `git push --no-verify`：它会连碎片检查和契约测试一起跳过」。没超 ⇒ 打印「预算检查通过（N / 上限 字节）」。
  - 读不出预算、预算模块载入失败、载入的不是本 checkout 的那份 ⇒ 拦（「没检查」不是「检查通过」）。被推提交里没有根目录 `CLAUDE.md` ⇒ 放行。
  - 薄调用（`.git/hooks` 里的 shim）没变：随本文件合入即生效，不用重装钩子。
  - 模块说明新增「根目录 CLAUDE.md 预算闸」一节，写明上面的数和取舍。
- `tests/test_changelog_guard_hook.py`：新增 `TestRootBudgetGate` 15 条（后 5 条是二次核对补的，见文末），都在临时仓库里装真钩子、用真实 `git push`：
  - 超预算被拦，信息里有超多少、最大的节、先问用户、别 `--no-verify`，远端 main 没动；
  - 恰好等于预算放行（边界与测试的 `<=` 同口径），并报出余量；
  - 没动根目录的推送不查，哪怕 main 上已超；
  - 两个会话各加 40 字节、各自没超，rebase 到一起 130 > 100 被拦；
  - 查的是被推提交，不是工作区；
  - 工作区里没提交的调预算，调大、调小两个方向都不算数；
  - 读不出预算、模块缺失、模块来自别处，都拦并说明「未被检查」。
- `tests/test_claude_md_partitions.py`：改为从 `claude_md_budget` 导入；新增两条——钩子按 `BUDGET_LINE` 能从真文件读出同一个预算（防止有人把那一行改成钩子读不出的写法）；`budget_in_source` 对读不出、两处、行尾注释都返回 None。

### 没做
- 没接 pre-commit：提交后几分钟内就会推，早那几分钟用处不大，还会挡本地的半成品提交。
- 分区的另几条检查（`paths:`、指针、引用）没进钩子：它们要导出整棵树再跑 pytest，触发也少，留给测试和 CI。
