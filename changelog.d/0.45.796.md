## [0.45.796] — 2026-11-20 — Fixed：Alpha Bot 深度页证伪条件「毛利率环比」在 Yahoo 新一季收入 / 毛利还空着时，改用 SEC 8-K 财报新闻稿（公司官方 GAAP 利润表）补

### 起因

用户 11-20 问 NVDA 深度页「毛利率季度环比下降 > 200bps」为什么显示「数据不够」。查明：NVDA 11-17 盘后发了 Q3 FY27 财报，Yahoo `quarterly_income_stmt` 已建出 2026-10-31 那一列但只有 EPS、收入 / 毛利是 NaN（11-20 仍空）；判定按设计不跳过缺数的最新一季 ⇒「数据不够」。10-Q（XBRL）要几周后才交。用户定「找能找到准确数据的地方代替」⇒ 选**随 8-K（Item 2.02）提交的财报新闻稿附件**：财报当天就在 SEC 上，是公司自己的 GAAP 简明合并利润表。

### Fixed / Added

- `alphabot/thesis_auto.py`：
  - `fill_income_from_press`：只在 Yahoo **最新一季缺收入或毛利**时才去 SEC，只补那两格，补上的行带 `source`（页面的事实句里写明「取自 SEC 8-K 财报新闻稿（文件名、提交日、季末）」）；没补上带 `fill_note`，「数据不够」的说明里写出为什么没补上（失败不消失）。永不抛。
  - `_press_release`：读 `data.sec.gov` 的提交清单，取季末之后 120 天内提交的、Items 含 2.02 的最近一份 8-K（同期的 5.02 人事 8-K 不算），在它的附件里找利润表（像新闻稿的文件名先试，最多 4 个）。
  - `parse_press_income`（纯）：按「Statements of Income / Operations」定位，表头单位（百万 / 千）与「Three Months Ended」后的日期都认出来才收，取第一列（本季）与第二列（去年同季）；认不出 ⇒ None，不猜。
  - `check_press_income`（纯）三道核对，任一不过就不补：收入 − 成本 = 毛利（差 ≤ 1 个单位）；新闻稿季末与 Yahoo 那一列相差 ≤ 10 天（Yahoo 按月末记，NVDA 季末是月底前的周日）；Yahoo 有去年同季时，新闻稿第二列的收入 / 毛利与它相差 ≤ 0.5%。
  - `SEC_CIK` 只登记要判毛利率的 NVDA / TSLA（测试核对与 `CHECKS` 一致）；`SEC_UA` 只写工具名、不带任何个人信息。`fetch_part` 新增注入接缝 `sec_get`：注入了 `yf_module` 而没给 `sec_get` ⇒ 不去 SEC（测试不出网）。`NEEDS` 里这条的来源说明改为「Yahoo 季度利润表（最新一季 Yahoo 还空着时，用 SEC 8-K 财报新闻稿补）」。
- `tests/test_alphabot_thesis_auto.py`：+15 条（全离线）：解析本季 / 去年同季两列与单位、别的科目名与「千」、认不出就拒；补上后判定为未触发且事实句注明来源；Yahoo 完整时一次都不问 SEC；算术 / 去年同季 / 季末对不上、还没有财报 8-K、SEC 出错各自写明原因且照旧「数据不够」；注入 Yahoo 不给 `sec_get` 不出网；CIK 与 `CHECKS` 一致；UA 不含 `@`。模块 import 白名单加标准库 `re` / `html`。
