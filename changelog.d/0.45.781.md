## [0.45.781] — 2026-11-17 — yf_daily：yfinance 吞掉取数异常后抛的误导性 TypeError 改名 `YFFetchMasked`（只改报错文字与计数，行为不变）
<!-- 认领：worktree-yf-masked-fetch-error 2026-11-17T10:36:02-07:00 5442570e -->

### Fixed
- `yf_daily.py`：`history()` 遇到 yfinance 1.2.0 `PriceHistory.history` 的「取数失败被吞」形状时改名抛出 `YFFetchMasked`。
  - 机制：`data = None` → GET / `.json()` 抛任何异常（curl (35) TLS、超时、非 JSON 的 429 文本）→ 缺省 `hide_exceptions=True` 下不抛也不记 → `data['chart']['result']` ⇒ `TypeError: 'NoneType' object is not subscriptable`。调用方看到的是像代码 bug 的报错，网络原因整条丢了。
  - 2026-11-17 MCP `alphahive_get_price_history` 报的就是这个；同一时段直调 yfinance 的期权链报了 curl (35) TLS。生产日志 `alpha_hive.log` 里 curl (35) 共 42 次、阵发（11-16 扫描 15:18:07–15:19:41 共 8 次，10-22 共 19 次），只在没被吞的期权链路径上看得见。
  - 只认「消息是 None 下标 **且** 回溯最内层在 `yfinance/scrapers/history.py`」这一种，其余 TypeError 原样抛。
  - `YFFetchMasked` 是 `TypeError` 子类 ⇒ 现有 `except TypeError` / `except Exception` 一条不变；空数据仍返回空帧。**评分冻结期内作废 0 条**：只改异常的类名与消息，成功路径与失败路径的控制流都没变。
  - 原始异常已被 yfinance 丢弃，这里拿不回来；消息只能说清「是取数失败、不是代码 bug」，并指名票与 `source`。
  - 新计数 `stats()["fetch_masked"]`（逐调用点同名键只在发生过时出现），经 scan_timing `yf_daily` 进来；本版**未接告警**。
- 不用 `raise_errors=True`（最初设想的修法）：它同时把「空数据返回空帧」改成抛 `YFPricesMissingError`，会改二十多个调用方（多数在 `final_score` 上游）的空数据路径，且该参数在 1.2.0 已弃用。

### Added
- `tests/test_yf_daily.py::TestMaskedFetchFailure`：真 yfinance 代码路径、底层 GET 抛异常（不联网）。正对照钉住 yfinance 1.2.0 确实把网络异常吞成 None 下标 TypeError（换版本先红）；改名 + 计数 + 仍是 TypeError；同消息但抛点不在 yfinance 的 TypeError 不改名；空数据路径不变。变异（关掉判据）⇒ 红。
