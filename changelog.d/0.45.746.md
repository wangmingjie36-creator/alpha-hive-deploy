**起因**：用户 11-06 回复上一轮的待决项：「放宽上限 60%」（追问后定为「总 60%，按我上面的筛选条件筛出最优标的然后开仓」）；「财报前 IV 偏高卖不是更划算吗」（规则本来就照卖，确认不改）；「covered call 要在那只股票涨的时候做，也和卖一样看综合条件哪个好卖哪个价位」（追问后定为「接货后涨 5%」）。RV 告警口径：用户认为 v0.45.744 已从根因解决，保持现状、不改。

### Changed
- `sell_put_wheel.py`（`_VERSION` → 0.45.746，新开 put / 新卖 call 的 `rule_version` 随之变）
  - **额度与张数**：删 `contracts`（固定 1 张）与 `per_name_cap_pct`（单只 20%）；新增 `sizing = "fill_total_cap_by_score"` 与纯函数 **`put_size`**——按综合分从高到低，每只开到「put 担保 + 持股 ≤ NAV × 60%」与「开仓后现金 ≥ 全部 put 担保」都容得下的最多张数；容不下一张 ⇒ `total_cap` / `no_cash`。额度会集中在综合分最高的那只，是规则的直接后果。
  - **covered call**：删 `call_dte_target` / `call_target_delta`，`call_dte_range` 25~50 → **30~50**，新增 `call_min_rise_pct = 5.0`。
    - 新增 **`call_rise_ok`**：截止场次收盘 ≥ 接货价 × 1.05 才卖；收盘取自 `rv_asof` 新增的 `close`（与 RV 同一份日线、同一个截止场次，末根不对就没有）。没涨够 ⇒ `not_risen`（skipped 带收盘、场次、门槛价），没有收盘 ⇒ `no_close`，RV 算不出 ⇒ `no_rv`。
    - **`pick_call`** 改为与 put 同一套：窗口内每个到期日 × 行权价 ≥ max(成本底线, 现价) 的合格 call，IV/RV ≥ 1，取「年化（bid ÷ 现价 × 365 ÷ 天数）× IV/RV」最高；同分规则同 put。签名改为 `(contracts, basis_floor, spot, as_of, rv_pct)`，返回 `(合约, 原因, info)`。「行权价 ≥ 现价」是我加的：价内 call 的权利金含内在价值，按年化排会专挑深度价内。
    - 选优循环抽成 `_best_by_score`，put / call 共用；`score_put` 加 `base` 参数（年化分母）。
    - 卖 call 的事件与持仓 call 腿记 `iv_pct` / `rv_pct` / `iv_rv` / `score` / `annual_yield_pct` / `close` / `close_session` / `trigger` / `rv_end` / `rule_version`。
  - 取 RV 抽成 `_run_for_date` 内的 `fetch_rv`，卖 put / 卖 call 共用；`all_rv_missing` 起含要卖 call 的持股标的。
  - 原因码表：删 `per_name_cap` / `no_delta`，加 `no_close` / `not_risen`，`total_cap` / `no_call_strike` 改写说明。删 `pick_expiry`（已无调用者）。
- `alphabot/wheel.py`：持股视图加 `call_trigger`（门槛价只经 `W.call_rise_ok` 算）；call 腿透出 `rule_version` / `trigger` / `close` / `close_session`。
- `alphabot/static/pages/wheel.js`：持仓表加「张数」列；call 列显示权利金 · 年化 · IV÷RV，没卖 call 时显示「收盘到 X 才卖」；跳过的 call 带明细。
- `alphabot/static/pages/help.js`：「额度与张数」「接货后」两条按 v3 重写，常量取自 `w.total_cap_pct` / `w.call_min_rise_pct` / `w.call_dte_range` / `w.min_iv_rv`。
