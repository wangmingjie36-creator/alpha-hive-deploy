## [0.45.784] — 2026-11-19 — Changed：alpha-hive-web 升级到 Next 16 / React 19（业务代码零改动）
<!-- 认领：chore/next-16 2026-11-19T19:59:00-07:00 e78c647f -->

### 起因

用户 2026-11-19 把本机 Node 从 25 升到 26 后，要求把 `alpha-hive-web` 从 Next 14.2.5 升到 Next 16。升级前先确认过：Next 14 在 Node 26 下能构建，所以这次升级不是为了修什么问题，而是跟进框架版本。

### Changed

- `alpha-hive-web/package.json`：
  - `next` 14.2.5 → **16.4.6**（保持精确锁定，不用 `^`）。
  - `react` / `react-dom` ^18 → **^19.3.1**；`@types/react` / `@types/react-dom` ^18 → **^19.3.0**。
  - 新增 `engines.node: ">=20.9.0"`（Next 16 的最低要求）。Vercel 会读这个字段，不再依赖后台的 Node 设置；后台设的是哪个版本还没查（待验证）。
- `alpha-hive-web/tsconfig.json`：由 `next build` 自动改写。必需的一项是 `jsx: preserve → react-jsx`（Next 16 走 React 的自动 JSX 运行时）；另外加了 `target: ES2017` 和 `.next/dev/types/**/*.ts`，其余只是重新排版。
- `alpha-hive-web/package-lock.json`：随上述依赖重新生成；顺带刷新了 caniuse-lite，目标浏览器列表没有变化。

### 为什么业务代码不用改

Next 15 起 `cookies()` / `headers()` / `params` / `searchParams` 都改成了异步，本项目一个都没用到。两个 API 路由读请求头用的是 `request.headers.get()`，这个接口没变。

### 验证

- 构建通过，TypeScript 检查通过，6 个路由全部生成，没有 warning。
- 用干净目录做了一次 `npm ci` 再构建（只用 git 跟踪的文件），通过。锁文件里有 `@next/swc-linux-*` 等 Linux 版二进制，依赖树里只有一份 React 19.3.1。
- 用 `next start` 实测：首页、`/success`、`/cancel` 渲染正常，控制台无报错；`/api/checkout` 用 Stripe **测试**密钥能拿到 `checkout.stripe.com` 链接；`/api/webhook` 不带签名时返回 400；「返回首页」客户端跳转和邮箱输入框都正常。

### 没做

- `@types/node` 仍是 `^20`：等确认 Vercel 用的 Node 大版本后再升。
- 没有在 Vercel 预览环境实际部署过。
