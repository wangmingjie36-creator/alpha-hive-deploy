## [0.45.773] — 2026-11-12 — Fixed：yfinance 并发 `download` 串数据（根因：全局字典竞态）——`yf.download` 进程内串行 + 所有调用点统一身份校验；评分冻结期真 bug 例外

### 起因

用户查 11-11 盘后扫描时问到编排器日志里的「yfinance 请求 VZ 却返回了 SOXX 的数据」。`market_intelligence._get_ma` 的注释把它归因为「限流时返回上一次成功请求的缓存帧」——**不对**：
10-29 一天串 25 次、10-30 串 15 次，当天 `429×0`。

**根因**：yfinance 1.2.0 的 `multi.download()` 把结果攒在模块级全局 `yfinance.shared._DFS`——每次调用开头 `shared._DFS = {}` 重建，工作线程往里写 `_DFS[ticker]`，
调用方轮询 `len(_DFS) < len(tickers)` 后 concat 整个字典。扫描 30 只票的并行线程各发约 9 次单票 download（政体均线 4 + 供应链 5），
同时在飞时互相清空 / 写进对方的字典 ⇒ 请求 A 拿到 B 的完整帧（或抛 `dictionary changed size during iteration`，被调用方吞成「不可用」）。
`yf_gate` 原来只限**速率**（令牌桶）、不限**同时在途个数**，所以管不到。离线复现（把 `yfinance.multi.Ticker` 换成桩）：2 个并发线程 32.5% 串数据、8 个 62.9%；
加进程级锁后 8 线程 480 次 0 次、无丢失调用。

**影响面（只读实测）**：① Guard 市场政体均线 `_get_ma`（旧代码只有这一处有身份校验，串了 ⇒ 「个股政体数据不可用」；11-09 AMZN / AMC / ABBV / T 的政体缺口就是它）；
② Scout 供应链 5 日涨跌 `get_supply_chain_signals`（每次扫描 150 次、**没有任何身份校验**，别家的涨跌被静默当成自己的一路写进 `supply_chain_signal` → Scout 分）。
②的检出法：同一标的（TSM / AMAT / ASML / SOXX）在不同票里的 5 日涨跌应当相同——每个扫描日 120 格里不一致的：10-29 59/111、10-30 9、11-09 7、11-11 9、10-13 4、10-27 2、11-06 2，10-28 与 11-05 为 0；
按「同一标的取众数」重算信号翻转的票 10-29 3 只、10-30 2 只、11-09 0 只、11-11 1 只（COST positive → neutral，Scout 分约 -0.3）。目标票自己那一路被串无法这样检出，上面是下限。

### Fixed

- `yf_gate.py`：`install()` 给 `yf.download` 套**进程级串行锁**（`_gated(..., serialize=True)`）。限流令牌在锁外取（别让令牌等待占着锁）；拿到锁后**复查冷却**（排队期间可能已有别人踩 429）；
  等锁有上限 `DOWNLOAD_LOCK_TIMEOUT = 300s`，超时抛 `YFDownloadLockTimeout`（⊂ `YFRateLimited` ⊂ `ConnectionError`，调用方当「该源不可用」降级，不拖死整轮扫描）；
  只锁 `download`，`Ticker.history` 等每实例自己的状态仍并行。`stats()` 新增 `download_serialized` / `download_lock_wait_s` / `download_lock_timeouts`。
- `yf_daily.py`：`download()` 对**所有** `source` 统一做身份校验（`_enforce_identity`）——返回里有没请求的票 ⇒ 丢掉那些列、请求了却没拿到的票标成「缺了」（refuse 的调用方据此当取不到）、计数。
  干净的调用不动帧（`tests/test_yf_daily.py` 的等价对拍仍全绿）。`stats()` 新增 `identity_mismatch` / `identity_foreign` / `identity_items`，`by_source` 条目只在出事时才多出 `identity_mismatch` 键。
- `alert_manager.py`：新增 `_check_yf_download_integrity`——`identity_mismatch > 0` ⇒ P2（装了锁后应恒为 0，非 0 = 锁被绕过或 yfinance 行为变了）；`download_lock_timeouts > 0` ⇒ P2；计数缺失 ⇒ `checks_skipped`。
- `scan_timing.py`：摘要行在串行过 download 时多一段 `[download串行N次/排队Ns]`——**上线时测不了负载下的耗时**（单次 download 实测约 2.85s、一轮约 270 次，最坏串行 ≈13 分钟，Step 2 预算余量 61 分钟放得下），让它每天自己报。
- `market_intelligence.py`：`_get_ma` docstring 更正成因（「限流缓存帧」→ 全局字典竞态）。仅注释。
- `swarm_agents/guard_bee.py`：`GENERATION_MARKS` 加 `yf_download_serialized`（成功与出错路径都写）。
