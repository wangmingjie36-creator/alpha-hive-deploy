## [0.45.747] — 2026-11-06 — Changed：接货账本 v3.1 允许加仓——已有未到期 put / 持股的标的在额度内照样按综合分再开一笔，作为同一只的另一个循环
<!-- 认领：worktree-wheel-composite-score 2026-11-06T17:15:45-07:00 f54ece22 -->

**起因**：v3（0.45.746）把额度改成按综合分装满张数后，生产三只各已有 1 张未到期 put（约占 41% NAV），而「同一只已有仓就不再叠加」没改 ⇒ v3 的张数规则最早要等 12-18 WMT 到期才用得上。问用户后定「允许加仓」。

### Changed
- `sell_put_wheel.py`（`_VERSION` → 0.45.747）
  - 持仓改按**循环号**（`cycle` = 标的-开仓日，`_lot_key`；缺循环号的旧行退回标的名）索引，一只可同时有多个循环；结算、卖 call、盯市、额度（`_reserved_and_shares` / `_nav_estimate`）都按循环逐个处理、用 `lot["ticker"]` 取链与价格。
  - 卖 put 不再跳过已有仓的标的；改为：同一只**一天最多新开一笔**（今天已开过的跳过——同日重跑幂等、循环号不撞），当天有结算延期的标的记 `settle_deferred` 不加。
  - RV 一轮里每只只取一次（`fetch_rv` 缓存），计数也只记一次：一只有多个循环、又要卖 call 又要加仓时不重复打 yfinance、不重复计。
  - 净值行的 `states` 改为按循环号（此前按标的；仓库里没有读者）。
- `alphabot/static/pages/wheel.js` / `help.js`：持仓表「每个循环一条（加仓后同一只会有多条）」；帮助页「额度与张数」写明允许加仓、一天每只最多一笔。
- `experiments/sell_put_wheel_prereg.md`：§2.1 / §3 改为 v3.1，§6 记 **v3.1**（附 v3 原文）。`.claude/rules/options-ledgers.md` 同步。

### 测试
- `tests/test_sell_put_wheel.py`
  - 额度不够时不加（skipped 只有 `total_cap`）；额度够时同一只开出第二个循环（循环号、担保、现金手算）；同日重跑即使额度里还有空也不开第二笔；两个循环各自到期、各自结算（先到期的接货，后到期的不受影响）；结算延期的标的额度够也不加。
  - 原「已有仓的标的不取 RV」改为「每只一轮只取一次、只记一次计数」。
