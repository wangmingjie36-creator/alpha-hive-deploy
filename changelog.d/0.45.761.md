## [0.45.761] — 2026-11-11 — Fixed：Alpha Bot 深度页对齐现行蜂群评分——票数只数真投票的蜂、标出哪些蜂进综合分、列出综合分各步、蜂名单跟着记录走
<!-- 认领：claude/alphabot-deep-sync 2026-11-11T05:04:54-07:00 94f07a67 -->

起因：用户指出 CodeExecutorAgent 早已退役（v0.45.750），而我在 0.45.760 的说明里把它历史记录中的 455 次失败当成了现状；
并要求按现行评分核对深度页（蜂群评分改过几次）。对照 `swarm_agents/queen_distiller.py` 与 144 个扫描日的记录后，查出四处没跟上：

### Fixed
- **票数数错了对象**：摘要用的是记录里的 `agent_breakdown`——`queen_distiller` 为历史可比保留的「全体」口径，把不投票的蜂也数进去
  （`NON_VOTING_AGENTS` = Bear、Guard，记录里自 2026-09-14 起有 `vote_excluded_agents`）。NVDA 11-10 页面写「6 只看空、1 只中性」，
  真投票的是 5 只：4 空 1 中性。现在 `deep_report._votes` 只数投票的蜂，并附加权票数；名单取**那一天记录里**的，没有这个键的老记录 = 全体都投。
- **没说哪些蜂真正进综合分**：现行权重下 `signal`、`risk_adj` 两维是 0，Rival（`ml_auxiliary`）与 Bear（`contrarian`）不在五维里
  ⇒ 进综合分的只有 Oracle、Chronos、Buzz 三只，但页面上七只蜂的分数并排摆着。`agents[]` 新增 `weight` / `in_score`，明细表分「投票」「进综合分」两列。
- **缺综合分各步**：0.45.760 二次检查时我删掉了「综合分由 A 调到 B」那句（当时把不同时期的记录混在一起比，以为差值不是共振造成的）。
  现行代码里共振这一步是确定的（`rule_score = 加权分 × (1 + boost%)`，2026-10 / 11 的 870 份里没触发共振的 580 份这两步完全相等）。
  新增 `pipeline`：五维加权 → 共振加成后 → 数据质量压缩后 → Guard 扣分后 → Bear 封顶后 → 最终，照记录里各步的分数排，页面只显示真变了的步。
  Bear 封顶之后到最终分之间还有别的调整（同期 171 份在这一段变了），记录里没有逐步的名字 ⇒ 写「其后的调整」，不起名字。
- **蜂名单写死成今天的七只**：回看老日子时，当时还在的 CodeExecutorAgent 不显示。名单改为跟着当天记录走（已知的按固定顺序，
  其余用记录里的原名；`RETIRED_AGENTS` 给已退役的挂「已退役」）。出错判据补上以 ❌ 开头的报错。

### Added
- `dimensions[].base_weight`（政体路由之前的权重；与当天权重不同时页面两列都显示）。
- `side_effects`：不靠权重、但能动综合分的通道（Guard 扣分、Bear 封顶、数据质量压缩、扣分合计封顶）与算了没用的诊断量
  （Rival 的模型分、GEX 直接加减分），一律取记录里的开关（`*_applied` / `ml_auxiliary_in_score` / `gex_regime_mod.applied`），老记录没有的开关不猜。
  GEX 那一项只读「用没用」、不读加减分的数值——`tests/test_gex_modifier_disconnected.py` 把读那个键的生产文件名单钉死，展示层不去当它的读者。
- 帮助页 `deep` 章节加一节，讲票数与权重为什么和别处不一样、以及回看老日子时读的是当时的口径。
- `tests/test_alphabot_deep_report.py::TestScoringSync`（7 条）。

### 原则
页面读的是**那一天记录里的口径**，不把今天的评分规则写死进展示层：以后再改评分（换权重、增减蜂、调投票名单），深度页不用跟着改。
