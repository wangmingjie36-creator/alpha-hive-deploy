## [0.45.740] — 2026-11-06 — Fixed：经济日历监视（Step 13）的「无法判定」不再被 7 天节流缓存，下一轮就联网重查；节流期内的结论行注明出自哪次检查
<!-- 认领：worktree-calwatch-retry-undetermined 2026-11-06T10:36:20-07:00 8dc6d742 -->

**起因**：11-04 起 Step 13 报「❓ 无法判定：cpi、nfp」（bls.gov 两页 `HTTP Error 403`），11-05 照旧。11-06 查明（四次手工请求 + 10-07 起留存的日志与 JSON）：
- 11-04~05 只真联网过一次：11-04 15:29，正赶上那轮代理探活 4/4 失败、编排器退回直连。bls.gov 前面的 Akamai 边缘**按网络拒本机直连**（IPv4、IPv6 都 403，带合规 UA 照样拒；走代理，同一请求 200）。同一天 FOMC、GDP 两站直连照常。
- 当晚 18:49 的重跑（已走代理）和 11-05 的扫描都在 7 天节流窗口内（`network_checked_this_run: false`，age 0 / 1），原样重放那次的 403：节流只豁免「有新日程待抄」和旧版 GDP 缓存，不豁免「无法判定」，要到 age 7（11-11）才会再联网。10-14 同形（10-21 自愈）。
- 不是 BLS 改了规则，也不是我们改了请求头：模块 10-21 后没动过，10-21 / 10-28 用同一份代码走代理拿到 200。用户在四个处置里选了「无法判定不进节流」。

### Fixed
- `economic_calendar_watch.py::check`：节流只重放**查到了结论**的表。缓存里任一张表没有可判定的结论 ⇒ 本轮不节流、五页联网重查、整份重写。「没有结论」含三种：上次抓取失败 / 看不懂；缓存里缺这张表（`_SOURCES` 新加的表）；缓存里多出 `_SOURCES` 已没有、又没结论的表（重查重写后它消失，不会天天重查下去）。
  - v0.45.68 在节流分支把缓存缺的表补成「无法判定」的那段补丁到不了了，已删。「没查到的表绝不算无新」改由节流条件承担：缺表 ⇒ 联网；抓不到 ⇒ 照实「无法判定」。

### Changed
- `economic_calendar_watch.py`：结果（`--out` 外壳顶层）新增 `upstream_checked_at` = `upstream` 出自哪次联网检查。本轮联网 ⇒ 本轮时刻（同一个值写进节流状态的 `last_checked_at`）；节流 ⇒ 上次的 `last_checked_at`。看一份 JSON 就知道结论新不新，诊断不必再翻节流状态文件。纯增键，编排器（`ORCH_READS`）不读它。
- `economic_calendar_watch.py::main` / `_render`：节流期内，`--quiet` 的每条结论行后缀「（上游结论出自 YYYY-MM-DD HH:MM 的检查，节流 7 天内不重复联网）」（`_cached_upstream_note`，挂在 `network_checked_this_run` 上、不挂在分支上）；本轮联网的不加注。`_render` 的节流行带上那次检查的时刻。编排器日志里 Step 13 那行 WARN 的上一行就是这条结论行。
- `economic_calendar_watch.py` 模块 docstring：
  - 新增「节流只重放『查到了结论』的表」一节。
  - 「User-Agent」一节改正：合规 UA 是**必要条件、不是充分条件**。「带邮箱形状的 token 就放行」只在走代理时成立；本机直连被 Akamai 通用拒页（`Access Denied … Reference #18.…`，约 400 B、0.3 s）拒，与 BLS 自家 UA 闸的 bot-policy 拒页（约 1.3 KB）不同。看拒页就能分辨该查 UA 还是查出口。

### 为什么这么修
- 「无法判定」是那次没问到，不是答案。把它缓存一周，等于把一个小时的网络故障放大成一周的盲区，而且日志看不出是旧结果：11-05 那条读起来像当天又 403 了。
- 缺表与「判不了」同等对待，两者都是「不知道」。只豁免后者的话，`_SOURCES` 新加一张表的那周，它会天天报「此源从未被成功检查过」。v0.45.574 为 GDP 第二页专门加 `gdp_cache_predates_next_year`，治的就是这个形状。
- 重查是整份（五页），不只重查没结论的那几张：与「有新日程待抄」不节流走同一条路径，`last_checked_at` 只有一个，结论都出自同一次检查。
- 不治「直连被拒」本身：那是网络出口的事（代理挂了退回直连）。代理挂掉的当天照样报「无法判定」，这是对的；修的是之后几天别再重放。
- 没改 `orchestrator_steps._calwatch_summary`（rc=1 摘要里的「上游暂无新日程可抄」不带出处）：rc=1 只在有新日程（那轮必然联网）或本地日历 stale 时出现，本地日历眼下健康；Python 结论行已带出处，就在它上一行。

### 代价
- 某源持续失败（长期封锁 / 页面改版 / 代理连挂几天）期间，每个交易日联网一次（五页，其中 bls.gov 两页），而不是每周一次。与「有新日程待抄」时天天联网同一档；每页一次 GET，零 API 费用。
