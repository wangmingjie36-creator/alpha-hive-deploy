## [0.45.748] — 2026-11-06 — Changed：暂停国会交易数据源（Quiver 端点 6 月起要凭证、06-23 后零数据）——不再发请求，产出与此前每天 401 时逐位相同，不用登世代边界

**起因**：扫描日志天天有一行 `Congress trades fetch failed: HTTP Error 401`。用户问国会交易这一项有没有必要留，没有就暂停或删掉（2026-11-06）。核下来没有必要留：
- **源已死**：401 的原因 11-06 用如实标识核实过。正文 `Authentication credentials were not provided.`，响应头 `www-authenticate: Basic realm="api"` ⇒ 端点改成要凭证了，不是封 UA / IP。Quiver 官方 API 页（11-06 读）：Hobbyist $30/月起，只限个人用途，没写免费档。`.swarm_results_*` 里最后一次有议员交易是 06-23，之后 4 个多月全空。
- **直接进总分的路是 0**：Scout 所在的 signal 维度权重自 2026-09-10（v0.45.176）起为 0，生产 `dimension_weights` 实测。
- **间接的路还在，但源活着时也很小**：国会项挪 Scout 分 ⇒ 可能把 Scout 方向推过 6.5 / 4.5 ⇒ Scout 那一票进共振加成和方向投票（Scout 不在 `RESONANCE_EXCLUDED_AGENTS`、`NON_VOTING_AGENTS` 里）。源活着时（03-16~06-23，53 个扫描日；名单每天 8~10 只为主，05 月单日最多 39 只）：
  - 每天中位数 5 只票有议员交易，其中 3 只的 Scout 分真被挪动（`congress_score ≥ 1` 才覆盖中性 5.0）；共 203 次，挪动 -0.40~+0.39。
  - 按当天 signal 权重线性估算，对总分的直接影响中位数 0.049、最大 0.172（03-25 AMZN，+0.39 × 0.441）。
  - 约 20 次让 Scout 方向翻线，其中 8 次当天该票触发了共振。翻线改没改掉当天的共振 / 投票结果，没重放过（待验证）。
- 每天还剩一次注定失败的请求和一行 WARNING。

**暂停，不删**：暂停后的产出与过去 4 个多月每天 401 时逐位相同，分数、方向、落盘、`signal_archive` 都不变 ⇒ 不用登世代边界。删掉（把国会项拿出 Scout 公式）反而要动分：Scout 分现在恒含 5.0 × 0.10 这个常数项，拿掉后其余四项重新归一，每只票的 Scout 分离中性都远约 11% ⇒ 方向可能变 ⇒ 共振与投票跟着变 ⇒ 要登世代边界。删除的好处只是少几行代码。

### 怎么恢复
1. 选源（下一节）。付费先问用户。
2. 在 `ic_rerun_readiness._COHORT_HISTORY` 登世代边界：换源会改 Scout 分和方向。共振加成前瞻检验（v0.45.242）会列出检验期内新增的边界。
3. `SOURCE_PAUSED` 改成 `False`，改 `tests/test_congress_source_paused.py` 的缺省断言。换源还要改 `_ENDPOINT` / `_fetch_raw` 和字段映射。

### 过程中的失误
- 注释初稿写的是「signal 维度权重为 0 ⇒ 国会项对总分贡献恒为 0」，只看了直接进总分的那条路。写本条目时核出 Scout 方向票这条间接路（见起因），提交前已改。暂停本身不受影响，产出逐位不变。
- 教训：**维度权重为 0 不等于这只蜂对总分没影响**。蜂的方向票还进共振加成和方向投票，判「某个输入影响不影响总分」时两条路都要查。
