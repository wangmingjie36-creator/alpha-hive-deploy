用户 2026-11-12 要求二次检查 769（三处解说）与 771（做市商与大额成交 + 悬停提示）。

### 先验证了一条前提（结论：成立）
「隔日验证」把**上一次**扫描的成交量对「这一次未平仓 − 上一次未平仓」。依据是未平仓隔夜才更新。用全量历史检验了对齐方向：
取成交量 ≥ 未平仓 5 倍且 ≥ 1000 手、前后三次扫描都相邻的 908 个合约（当天必有大量新开仓）——
- 按现行对法（下一次 − 这次）：未平仓增量 ÷ 成交量的中位数 **0.67**，89% 的合约 ≥ 10%；
- 按错一天的对法（这次 − 上一次）：中位数 **0.01**，只有 4% ≥ 10%。
另：相邻交易日下 `|未平仓变化| ≤ 成交量` 这条不可能被违反的约束，现行对法 6425 个里 98.8% 满足。

### Fixed
- **上一次扫描不在交易日时，隔日验证全部误判**：两次记的是同一份未平仓（都是之前最后一个交易日收盘的），差值恒 0 ⇒ 每个合约都被判成
  「基本没留下」。历史上有过周末扫描（2026-05-15 周五 → 05-17 周日是有效的，周日那份已更新；出错的是「上一次本身在周末」）。
  `options_compare.weekdays_between`（纯算术，不 import datetime；与标准库逐日对照一致）数 `[上一次, 这一次)` 里的工作日：
  0 ⇒ `follow.available=False` + `no_session_between`，隔日验证与未平仓增减都不做。
- **两次扫描隔了几个交易日时没有提醒**：全量 143 组相邻扫描里 18 组如此，此时上述约束有 16.5% 被违反（未平仓变化含好几天，成交量只是一天的）。
  `sessions_covered > 1` ⇒ 加一条「注意」；页面的日期说明按覆盖的工作日数写（1 个 ⇒「发生在某日那个交易日」）。不认假日，遇假日会多提醒一次。
- **柱状图悬停提示多出「series0」**（v0.45.771 自己带进来的）：ECharts 给未命名系列的缺省名是 `"series" + 空字符 + 序号`，过滤规则没认那个空字符。
- **IV Rank 的解读写死「过去一年」**：真 IV 历史攒够后（约两周）窗口是已攒下的天数 ⇒ `hv_proxy` 才写「过去一年」，其余写「所用历史窗口」。
- 隔日验证做不了的原因分开：`no_oi_detail`（没有逐合约未平仓明细）/ `no_session_between`，都登记了人话文本。
