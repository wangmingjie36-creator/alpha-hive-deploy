# changelog.d/ — 每个版本一个文件（v0.45.728 起）

`CHANGELOG.md` 已冻结为历史档案（最大号 0.45.728）。**新条目一律写在这里**，一个版本一个文件
`changelog.d/<版本>.md`。格式与判据的唯一真相在 `changelog_fragments.py` 的模块 docstring，本页是速查。

为什么：此前所有会话都往 `CHANGELOG.md` 顶部插条目，号不同也照样冲突（10-01 起 main 上九成提交动了它），
解冲突成了例行公事，也就成了事故源。现在不同的号是不同的文件，rebase 不再冲突；只有真撞号才冲突。

## 开工：占号

```bash
/usr/local/bin/python3 changelog_fragments.py claim "一句话说明" --push --trailer "Co-Authored-By: …"
```

- 它在 **origin/main 上**另建一个只含 `changelog.d/<号>.md` 的提交，推送、以 `git ls-remote` 核实成功，
  再带进当前分支（落后就快进，否则 cherry-pick）。不碰你的分支内容和工作区，做到一半也能占号。
- 号被别人抢先 ⇒ 推送被拒 ⇒ 工具自动取下一个号重推（最多 5 次）。
- 推不了 main 的会话**不带** `--push`：照它打印的命令推送，推完在**同一个 checkout 里**再
  `/usr/local/bin/python3 changelog_fragments.py adopt <提交>`（打印的命令已带 `cd`）。**推上去之前号没占住。**
- 推完之后的提示照字面做：说「号多半已经占住」「号已占住」时**别重跑 `claim`**（会再占一个号），照它给的
  `adopt` 命令带进当前分支。`adopt` 可以放心重跑：已经带进来（认领行一致）就什么也不做，cherry-pick 撞冲突会自动撤回。
  `claim` 会转述 pre-push 守卫的输出；提示「没装 changelog_guard 钩子」就照给的命令装。
- **别手写碎片**：每个碎片必须恰好有一行认领注释 `<!-- 认领：<分支> <时刻> <8 位十六进制> -->`，
  只有 `claim` 会写它（理由见下面「撞号」）。

## 完工

把碎片标题里的 `占位（进行中：…）` 换成正式标题，在下面写正文
（`Added` / `Changed` / `Fixed` / `Removed`，注明文件名与改动摘要）。**认领那行原样保留。**

```
## [0.45.729] — 2026-11-05 — 正式标题
<!-- 认领：claude/xxx 2026-11-05T09:12:33-08:00 9f3a1c07 -->

### Fixed
- `foo.py`：……
```

提交前可自查：`/usr/local/bin/python3 changelog_fragments.py check`（与 pre-commit / pre-push / 全量测试同一套判据；
查的是工作区里**被跟踪**的文件：未跟踪 / 被忽略的副本不算，`git add` 进来就算）。

## 撞号

按 `claim` 占号不会撞出冲突（撞号只表现为推送被拒、自动换号）。只有绕过它手写碎片时，rebase 才会停在
`AA changelog.d/<号>.md`——说明别人先占了这个号：

1. **保留 main 上那份**：`git checkout origin/main -- changelog.d/<号>.md`，然后 `git rebase --continue`。
2. rebase 完成后 `claim` 一个新号，把你的内容写进新号的碎片。

认领注释保证两份碎片内容一定不同：内容相同的同号碎片在 rebase 时会被**静默合掉**（后来者的占号提交被当成
「已在上游」丢弃，双方都以为占到了，实测）。解冲突时选错边、盖掉了别人的碎片 ⇒ 认领注释变了 ⇒
pre-push 拦下。

## 判据

| 情形 | 判定 |
|---|---|
| 文件名不是 `X.Y.Z.md`：前导零、`.MD`、iCloud 副本 `0.45.729 2.md`、子目录、除本页外的其他文件 | 红 |
| 首个非空行不是 `## [号] — YYYY-MM-DD — 标题`；号 ≠ 文件名；不止一个 `## [` 标题 | 红 |
| 冲突标记；空文件；不是占位却没有正文 | 红 |
| 认领注释缺失、不止一行、格式不对 | 红 |
| 碎片号 ≤ 档案 `CHANGELOG.md` 的最大号 | 红 |
| 推送删掉 main 上已有的碎片，或改了它的认领注释 | 红（pre-push） |
| 往冻结档案 `CHANGELOG.md` 加新号、增删条目 | 红 |
| 跳号、占位未完成 | 不红，`status` 里列出 |

遗弃的号：推上 main 的碎片不删（删了 pre-push 会拦），把标题改成 `占位关闭：<原因>`、正文写一句为什么。

## 其他命令

- `status`：最大号、下一个号、进行中的占位（含档案里冻结前占的号）、跳号。号以 `claim` 推送成功为准，这里只是快照。
- `render [--limit N] [--rev 提交]`：合并视图打印到标准输出（要存文件就 `> 路径`），碎片在前、档案在后。**不提交生成结果**——提交了就是新的冲突热点。

## 过渡期

冻结前已在 `CHANGELOG.md` 里占的号**就地完成**：照旧改标题、补正文，不加新标题（冻结断言只看条目数与最大号）。
`status` 会把它们和碎片里的占位一起列出来。
