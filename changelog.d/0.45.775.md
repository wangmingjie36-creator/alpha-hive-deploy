## [0.45.775] — 2026-11-14 — Changed：全局标的（政体的 ^GSPC / SOXX、供应链的 TSM / AMAT / ASML / SOXX）一轮扫描只取一次、30 只票共用；失败不缓存、连续 3 次失败后本轮不再试；整轮没取到 ⇒ P2

### 起因

用户 2026-11-14 问「既然别的票也用 SOXX，能不能用别的票取到的数给 ABBV 用」，随后定「一轮只取一次，30 只票共用，然后补 ABBV」。

11-13 ABBV 的政体板块层「SOXX 数据不可用」：30 只票的线程各取一遍 SOXX，其中一次下载在 yfinance 内部抛了异常、被它自己吞掉（`PriceHistory.history` 的 `except Exception: if not YfConfig.debug.hide_exceptions: raise`，默认 hide ⇒ `data=None` ⇒ `data['chart']` 抛 `TypeError: 'NoneType' object is not subscriptable`；真正的第一异常没人记，当天同一秒还有一条不受串行锁管的 `Ticker.history`（DELL 的 HV）吃了同一个 TypeError ⇒ Yahoo / 网络侧瞬时事件）。其余 29 只票的同一层逐只相同（`SOXX $149 跌破 20MA $157`）。链上没有任何一层重试：yfinance `network.retries=0`、`_get_ma` 失败即 `continue`。
每轮 270 次单票 `download` 里约 180 次是对同一个标的的重复，每一次都是一次「这一层缺」的机会。

### Changed

- `market_intelligence.py`：新增扫描级共享表（`begin_scan_shared()` / `end_scan_shared()` / `shared_stats()` / `_shared_slot`）。
  - `detect_market_regime`：宏观层 `^GSPC`（200MA）与板块层 `SOXX`（20MA）经 `_get_ma_global`——同一个键整轮第一个到的线程取、其余等它取完直接用；个股自己的 50MA / 20MA 仍逐票取。
  - `get_supply_chain_signals`：四个同行（TSM / AMAT / ASML / SOXX）经共享表；目标票自己那一路仍逐票取。
  - **只缓存成功**：空帧 / 身份校验丢弃（nan）/ 异常都不缓存，下一个线程再试 = 天然重试；同一个键连续失败 `SHARED_MAX_FAILS`（3）次，本轮不再试（行情全断时不让 30 个线程各等一次超时），调用方照旧当「这一层取不到」。
  - 每个键一把锁、拿着锁取数；与 `yf_gate` 的 download 串行锁的加锁顺序恒为「键锁 → download 锁」。
  - **没开共享表**（单票 CLI / MCP / 测试 / 深度分析）⇒ 行为逐字等于改动前：每次都自己取，不跨调用缓存；共享表只活在一轮扫描里，不跨日串数据。
- `alpha_hive_daily_report.py`：`_init_scan_context` 在注入宏观快照旁开共享表；`run_swarm_scan` 在并行阶段（含重试轮）结束后关，并把统计打进日志（有键整轮没取到 ⇒ WARNING）。
- `scan_timing.py`：`counters()["shared_quotes"]`（`shared_stats()`）；摘要行只在出过失败重试 / 有键没取到时才多一段。
- `alert_manager.py`：`_check_shared_quotes`——`unfilled` 非空（有一个键整轮没成功取到过）⇒ P2。共享后这类缺口从「缺一只票的一层」变成「30 只票一起缺」，而它原本就没有任何告警；重试后取到了不报；计数缺失 ⇒ `checks_skipped`。

### Added

- `tests/test_scan_shared_global_quotes.py`（15 条，全离线）：30 个并发线程下 ^GSPC / SOXX 整轮只下载 1 次、个股自己的两路各 2 次；与不共享时逐项相同；没开共享表时每只票各取一遍（行为等于改动前）；begin 清旧、end 关；失败不缓存且下一只重试取到、连续 3 次失败后不再试；身份校验丢弃与异常都不锁死键；供应链同行只取一次、一个同行失败由下一只补上；接线（开 / 关的位置，关在重试轮之后）；告警与摘要行。
