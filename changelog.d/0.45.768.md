## [0.45.768] — 2026-11-11 — Fixed：出错蜂的占位值（5.0 分 / 中性方向）不再流进 agent_directions、signal_archive 与网站分歧度
<!-- 认领：claude/oracle-no-fake-score 2026-11-11T13:17:46-07:00 cdda5ca0 -->

**起因**：v0.45.767 的报告里列了「出错蜂的中性方向仍流进 ML 特征 agent_agreement / 共识度归档信号 / 逐蜂准确率诊断；5.0 分进 signal_archive」，用户 11-11 答「一起处理了」。

出错的蜂照样带着 `swarm_agents.utils.make_error_result` 的占位 `score=5.0` / `direction="neutral"`。蜂后自己从不用它：`valid_results` 按 `error` 键排除，评分、计票、`agent_breakdown` 都不数。漏的是四个不看 error 键的下游，那张「中性票」蜂后自己从没数过。

### Fixed
- **`models.agent_record_failed`（新增，判据唯一实现）**：`error` 为真，或 discovery 以 `Error` / `❌` 开头。
  - 老记录只有前缀这一条线索：`agent_details` 自 v0.45.182 才透出 `error` 键。
  - 全部 2721 份归档实测：`error` 为真的 244 条全部同时带前缀；只有前缀的 385 条全在老记录里 ⇒ 两条取或在历史上等于只看前缀。
  - Alpha Bot 深度页的 `deep_report._failed` 只看前缀（纯函数、只 import options_compare，没改），在全部历史上与它逐条相同。
- **`swarm_agents/queen_distiller.py`：`agent_directions` 只记有效结果**，与同函数里 `agent_breakdown` 的 `_all_dirs` 同一口径。
  - 这一处是 ML `agent_agreement` 两端的共同来源：训练端读 `predictions.agent_directions`，服务端读 `swarm_results[T]["agent_directions"]`，公式相同 ⇒ 改在源头，两端一起变，不造 train/serve skew。
  - 逐蜂准确率诊断（`backtester`）读同一列，出错的蜂缺席即跳过。
  - 出错记录仍完整留在 `agent_details` 里（带 error），审计轨迹不丢。
- **`signal_archive.py`**：`agent.<蜂>.score` / `.direction` 对出错的蜂返回 None（不入档）；`composite.swarm_agreement` 跳过出错的蜂。
- **`dashboard_renderer.py`：网站「蜂群分歧度」跳过出错的蜂**，不再把占位 5.0 算进标准差 / 极差、把占位中性算进共识度。单只票那段原样抽成 `_swarm_divergence_entry`，好测。
