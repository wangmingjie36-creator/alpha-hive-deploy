## [0.45.786] — 2026-11-19 — Changed：Alpha Bot 成交榜的「约成交额」改为「约时间价值额」——扣掉内在价值，只算时间价值；当天到期的占比另行写出
<!-- 认领：claude/volume-time-value 2026-11-19T20:02:24-07:00 88c195f2 -->

### 起因

v0.45.776 的成交榜在真实链上看（2026-11-16 NVDA）：「约成交额 Call / Put」写着 $611M / $1.01B，像是钱都去了 Put；Put 侧 63% 其实来自实值合约，其中有 2028-12 到期、行权价 340 / 350 的深度实值 put，一张 $190 多、几乎全是内在价值（多是替代持股、对冲或组合里的一条腿）。另外当天到期的合约按此刻中间价算，和早些时候的成交价差很远。用户 11-19 定「只算时间价值」。

### Changed

- `alphabot/volume_board.py`：
  - 新增 `intrinsic_value(side, strike, S)`；每行加 `intrinsic`、`time_value`（中间价 − 内在价值）、`time_value_below_intrinsic`、`tv_notional_est`（成交量 × 时间价值 × 100），**删掉** `notional_est`。
  - 中间价比内在价值还低（延迟的现价与报价对不上、深度实值报价偏低）⇒ 这一行的时间价值记 0 并标记，汇总里有成交的这类合约计数 `n_time_value_below_intrinsic`（页面写出来），不吞掉。
  - 汇总 `call_notional_est` / `put_notional_est` 改为 `call_tv_notional_est` / `put_tv_notional_est`，并新增 `zero_dte_tv_share_pct`（时间价值额里当天到期合约的占比——这部分按此刻价算偏差最大、扣不掉，只能写出来）。
  - 排序键 `notional`（约成交额）改名 `time_value`（约时间价值额）；免责语同步。
- `alphabot/static/pages/volume.js`：KPI 改成「约时间价值额 Call / Put」（副行写「已扣内在价值；其中当天到期占 N%」）；表格加「时间价值 / 内在」列，「约成交额」列换成「约时间价值额」；中间价低于内在价值的个数写在表下。本机记着旧排序键 `notional` 的，读取时换成 `time_value`（不然一打开就提示「筛选被拒」）。
- `alphabot/static/pages/help.js`：「标的 · 成交榜」一节改写这一项的口径与理由。
- `alphabot/CLAUDE.md`：成交榜子条写明新口径，并注明别改回连内在价值一起算。
- `tests/test_portfolio_greeks_bid_zero.py`：`volume_board._row` 的报价字段读者登记理由同步改写。

### Added

- `tests/test_alphabot_volume_board.py`：虚值 / 实值各自的时间价值；深度实值的长期 put 不再把它那一侧撑大（v0.45.776 的反例）；中间价低于内在价值记 0、计数只数有成交的；当天到期占比。旧的 `notional_est` 断言、HTTP 路由的排序键随之改。

### 验证

- 11-19 晚上（22:05 ET）CBOE 对 NVDA 返回 307 → 403（走代理与不走代理都一样），用真实 CBOE 链看页面**没做成，待验证**。
- 改用 Yahoo 的 NVDA 链（Alpha Bot 的备用源，同一个 `volume_board` 代码）离线算了一遍：旧口径 Call / Put $346M / **$3.17B**（Put 侧 $3.09B 来自实值）→ 新口径 $267M / $187M；按约时间价值额排的前几名是近月平值附近的合约。收盘后 Yahoo 的报价里有 258 个有成交的合约中间价低于内在价值（时间价值记 0、页面计数）——盘中 CBOE 链上这个数应该小得多，待验证。
