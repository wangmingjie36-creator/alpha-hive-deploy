## [0.45.793] — 2026-11-20 — 论点失效条件：删掉把每条写死成「✅ 安全」的死渲染器，加守卫不许生产代码读手写的 current_status
<!-- 认领：chore/thesis-current-status-dead 2026-11-20T09:46:40-07:00 d965b269 -->

用户问「日报和网站展示没展示 current_status」并要求从根因解决，选了方案 A。

查证结果：`thesis_breaks_config.json` 里每条条件的 `current_status`（如「⚠️ 监管风险中等」）是 2026-03-09 手写的散文快照，此后 8 个月没人更新过，
也**没有任何写入者**（仓库内无；仓库外唯一写过这份配置的 `深度分析报告/规则/weekly_analyzer.py` 自 2026-09-13 v3.2 起不再写它，
见 0.45.215）。它唯一的读者是 `ThesisBreakMonitor.generate_html_section`——只被模块 `__main__` 示例调用，日报（`market_intelligence`
读 metric / id）、网站（`dashboard_renderer` 读 metric + trigger）、Alpha Bot、LLM 提示词都不读；而它把监控表每一行**写死**成「✅ 安全」，
条件真触发了也照样显示安全。数据根与 gh-pages 产物里零命中。

### Removed
- `thesis_breaks.py::ThesisBreakMonitor.generate_html_section`（约 170 行 HTML + 内联样式）与 `__main__` 里对它的调用。
  `_check_condition` docstring 注明本模块只读 id / trigger、`current_status` 生产代码一律不读。
  配置文件本身不动（字段留给人看；改写条件措辞是另一件事，等用户定）。

### Added
- `tests/test_thesis_current_status_unread.py`：生产 Python（排除 tests / experiments / 退役归档）出现字面量 `"current_status"` 即红，
  前端 JS / HTML 模板按文本查；`generate_html_section` 回来也红。
  - ⚠️ 首版扫描器只看独立的字符串 token，拿删除前的真文件去扫**一处都没抓到**：Python 3.11 里整个 f-string 是一个 STRING token，
    渲染器那 3 处读法全在 `f"...{condition['current_status']}..."` 里。补了 f-string 一支，并把被删渲染器的原文摘录进测试做反向自证（必须抓到 3 处）。
  - 反向自证不从 git 历史取：CI 的 `actions/checkout@v4` 缺省浅克隆（fetch-depth 1），历史提交不存在。

### 测试

- 整套：14642 passed、0 failed（2 xfailed，19 分 39 秒；与另一个 worktree 的相关测试并跑，耗时不可比）。
