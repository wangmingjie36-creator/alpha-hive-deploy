### Fixed
- `economic_calendar_watch.py::check`：**上次检查晚于今天就不节流**（理由 `last_check_after_today`）。
  - 这种情况出在 `--today` 往回钉的回放，此时 age 为负。负数也满足 `age < max_age_days`，此前被当成在节流窗口内：回放不联网，原样报出之后那次检查的结论。
  - 生产扫描传的是当天日期，不受影响。
- `upstream_checked_at`（v0.45.740 新增）**现在带本机时区偏移**（`2026-11-06T15:00:12-07:00`）。
  - 此前它是不带偏移的本机时间，而同一份 JSON 里的 `generated_at` 是洛杉矶时间，2026-11-01 起冬令时两者差一小时。
  - 同一个值照旧写进节流状态的 `last_checked_at`。`_days_since` 取的是它自己偏移下的日期，算法不变。
  - `_upstream_stamp` 写出偏移（`2026-11-06 15:00 UTC-07:00`）；v0.45.740 写下的无偏移旧值照旧显示（`2026-11-04 15:29`）。
- `orchestrator_steps`：**Step 13 编排器自己的两句结论，节流期内也注明出处。**
  - 两句是：rc=0「✅ Step 13：宏观日历健康，上游无新日程」，rc=1 摘要里的「上游暂无新日程可抄」。
  - 做法是照抄生产方写的 `upstream_cached_note`（`_calwatch_cached_note`，封顶 200 字）。
  - 旧格式 JSON 和 v0.45.743 之前的 JSON 没有这个键 ⇒ 一个字不加，与 B 之前冻结副本的逐字对照不受影响。
  - 模块 docstring 加刻意改动 (j)。

### Changed
- `economic_calendar_watch.py` 的结果（`--out` 外壳顶层）纯增三个键：
  - `throttle_skipped_because`：本轮为什么没节流，空列表 = 节流了。
    - 取值：`force` / `no_previous_check` / `last_check_after_today` / `window_expired` / `action_pending` / `gdp_cache_predates_next_year` / `unresolved_in_cache`，几条同时成立就都列。
    - 节流判据改成「这张列表为空」。与 v0.45.740 的布尔式逐项等价，只多了上面那条负 age。
  - `unresolved_in_cache`：缓存里没有结论的表。v0.45.740 算出来只当布尔用，随即丢掉。
  - `upstream_cached_note`：节流期内那句「（上游结论出自 … 的检查，节流 7 天内不重复联网）」，本轮联网为空串。
    - `main()` 的结论行改为照抄它，编排器抄的也是这一句：措辞与时刻格式只在 `_cached_upstream_note` 一处。
