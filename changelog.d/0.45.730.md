## [0.45.730] — 2026-11-05 — Fixed：v0.45.726 二次检查——横幅改说「新旧混用」、服务比页面旧也挂横幅、测试清掉继承的 GIT_* 变量
<!-- 认领：worktree-restart-banner-paper-cooldown 2026-11-05T08:50:47-07:00 3f25b094 -->

**起因**：用户要求二次检查 v0.45.726（页脚代码版本 + 「代码已更新」横幅）有没有 bug。逐项复核、实测后修了三处（A–C）；另记一条不属于本版本的 CI 红。

### Fixed
- **A. 横幅、帮助页、docstring 把机制说错了**：726 写的是「Alpha Bot 只在启动时载入代码」「重启 Alpha Bot 才会用上」。实际上，没重启的进程是**新旧混用**：
  - `index.html` 每次请求都现读磁盘（`no-store`），`/static` 下的 JS / CSS 也每次向服务端核对（`no-cache` + ETag），所以刷新后的页面就是新的。
  - `service.py` 有 36 条写在函数里的 import（AST 计数）。启动时还没载入过的模块，第一次用到时载入的是磁盘上的新版本。
  - 其余仍是启动时的旧代码。新旧之间的接口一变，就可能出错。

  修改：
  - `alphabot/static/app.js`（`codeBannerText` / `RESTART_HOWTO`）：横幅改为「代码已更新 · 磁盘上的代码新了 N 个提交（运行中 X → 磁盘 Y）。服务还在跑启动时的代码，刷新后的页面和部分功能会读到新代码，新旧混用可能出错——请重启：页脚「停止服务」后，再双击 Alpha Bot.app 或重新运行启动命令」。
  - `alphabot/static/pages/help.js` 的「代码版本」一行同步更正。
  - `alphabot/code_version.py` 和 `alphabot/server.py::create_app` 的 docstring 同步更正：「重启生效」横幅的叫法改为「代码已更新」横幅。判定逻辑没动。
- **B. 726 之前起的服务配上快进后的新页面 ⇒ 不挂横幅**：
  - 页面文件每次现读磁盘，所以生产克隆快进后，旧进程送出的已经是新页面。
  - 旧进程的 `/api/meta` 里没有 `code` 键，726 的判据 `cv && cv.stale === true` 为假，页脚只写一句——偏偏这正是最该重启的时候。

  修改：
  - `alphabot/static/app.js::refreshMeta`：`/api/meta` 里**没有 `code` 这个键**（按键判，不按值判）⇒ 挂「服务比页面旧」横幅（`OLDER_SERVER_BANNER`），页脚写「代码版本：服务端没报（它比这个页面旧，见顶部横幅）」。
    - 依据：磁盘只往前走，页面每次现读。「页面认得 `code`、服务不报」只可能是服务旧。
    - 726 之后起的服务一定报 `code`：`status()` 不抛，总是返回 dict。
  - 已经开着的旧页面（726 之前的 JS）不认识这个横幅，要**刷新一次页面**才会出现。
  - 今天的生产正是这个情形：06:52 起的 Alpha Bot 跑的是 726 之前的代码（`/api/meta` 有 `outbound`，没有 `code`）。730 推上 main 后，生产克隆在下一次扫描时快进，刷新页面后应挂这条横幅（待验证：以那次快进确实包含 730 为准）。
- **C. 测试被 git 钩子或 `rebase -x` 拉起时，会改到真仓库**：
  - 继承下来的 `GIT_DIR` / `GIT_WORK_TREE` / `GIT_INDEX_FILE` 会让测试对临时仓库的 `git -C <tmp> commit / checkout --orphan / reset --hard` 打到这三个变量指的仓库上（`-C` 不覆盖它们）。
  - 诱饵仓库实测：不清这三个变量时，诱饵被切到孤儿分支、塞进 10 个提交，工作区被 `reset --hard`，而 19 条测试里 18 条照样绿。

  修改（`tests/test_alphabot_code_version.py`）：
  - autouse 夹具清掉 `changelog_guard._GIT_LOCATION_VARS`，与钩子共用一份清单。
  - 新增 `TestInheritedGitLocation`：子进程 pytest 带着指向诱饵的三个变量，跑两条真 git 测试；断言结果是 2 passed，且诱饵的分支、HEAD、提交总数都没变（约 1 秒）。

### 核过、没问题的
- `/api/meta` 是同步端点（跑在线程池里），`status()` 每次请求都求值、缓存 30 秒；`create_app` 只建一次 `CodeVersion`。
- 点「停止服务」后窗口自己关上、启动器退出，再双击 .app 起的是新进程。
- 在 .app 的启动环境下（PATH 只有 `/usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin`，没有 LANG），git 可用，中文提交说明解码正常（Python 3.11 的 UTF-8 模式）。
- CI（ubuntu、浅克隆）上 726 的 19 条全绿；「`__version__` 写进 Info.plist、不跟代码走」属实。

### 预期（不是 bug）
