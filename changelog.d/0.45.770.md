## [0.45.770] — 2026-11-11 — Changed：Oracle 期权链取不到弃权时，Bear 照抄它的判定、不再自己重取同一条链
<!-- 认领：claude/oracle-no-fake-score 2026-11-11T14:06:41-07:00 d55fe9b3 -->

**起因**：用户 11-11 问「为什么不用已经取到的期权链」。

- Oracle 取到链时，Bear 本来就读 Oracle 的板上条目，不另取。
- v0.45.765 起 Oracle 期权链取不到就弃权、不上板（板上一条中性条目会被 Guard 普查当成同伴票）。⇒ Bear 读不到条目，会对刚判过「这一轮取不到」的同一条链再取一次，多半白取，每只票约 2~47 秒。
- 能复用的不是链，是「取不到」这个结论。用户答「沿用」。

### Changed
- **`pheromone_board.py`：新增弃权登记** `record_abstention(ticker, agent_id, reason)` / `get_abstention(ticker, agent_id)`。
  - **不是条目**：不进排行榜、定点条目、存活视图、共振、普查、快照，也不落库。
  - 照条目的墙钟过期兜底（同一个 `ENTRY_MAX_AGE_S`）。
- **`swarm_agents/base.py`：`_record_abstention`**，写板机制放基类，同 `_publish`。
  - 读板对账测试把 `self.board.<非 publish 属性>` 一律当读点，所以蜂模块里不直接写。
  - 替身板没有这个方法 ⇒ 不登。
- **`swarm_agents/oracle_bee.py`**：
  - 每次 `analyze` 开头先清掉自己对这只票的旧结论，放在一切早退之前。同一只票重试时整套蜂重跑。
  - 弃权分支登记自己的标签：样本链 ⇒ `unavailable`，OptionsAgent 抛异常 / 返回空 ⇒ `fallback`。
  - **结果造好之后才登记**（二次检查修）：造结果时抛异常会变成普通出错结果，板上不能留着弃权判定。
- **`swarm_agents/bear_bee.py`**：读不到 Oracle 条目时先查登记。
  - 读到 ⇒ 照抄标签进 `data_quality.options`（同 v0.45.639 的读板路径），options_bear 留 0，不产 options_data，**不构造 OptionsAgent**。
  - 只认 `unavailable` / `fallback` 两个取值。没登记、认不出、替身板 ⇒ 照旧自取（Oracle 在别处出错、不在本行时就是这样）。
  - 新增世代印记 `details.options_no_refetch_on_oracle_abstain: True`；日报合成回退（`alpha_hive_daily_report._generate_synthetic_swarm_results`）同写。
- 顺带：`fallback` 那种弃权下 Bear 的期权标签与 Oracle 一致了。765~769 Bear 自取失败记 `unavailable`（返回空则不记），Oracle 记 `fallback`；现在两边都是 `fallback`。两个标签同在 Queen 的 PROXY_SOURCES，对 data_real_pct 的作用相同。
- `PheromoneBoard.clear()` 同时清弃权登记（二次检查补；生产不调 `clear()`）。
