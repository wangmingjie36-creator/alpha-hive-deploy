# 接货型卖 put 纸面账本 · 规则登记（v0.45.720，2026-11-04）

> **这是测量账本，不是检验。** 几只标的、几个月的样本证明不了任何优势；它的用处是把每一笔真实结果摆出来，
> 并与两条基准并排。规则在**看任何结果之前**写在这里；改任何一条 = 在 §6 记一次修订。
> 不构成投资建议。我对「段永平式」做法的理解只是公开说法的大意（只卖愿意持有的公司、行权价 = 愿意买入价、
> 现金担保、被行权就接货），**细节待用户确认**，规则里每个数都是主观设定。

## 2. 规则

### 2.1 账户与额度
- 纸面本金 $100,000，独立账本（`PATHS.sell_put_state`），**不并入**卖权选择器预注册、跨式预注册，也不碰它们的账本。
- （v3）**没有单只上限、张数不固定**：put 担保（行权价 × 100 × 张数）+ 持股市值 ≤ NAV 的 60%（开新 put 之前判）；另须开仓后现金（含收到的权利金）≥ 全部 put 担保。按 §2.5 的顺序，每只开到这两条都还容得下的最多张数（`sell_put_wheel.put_size`），容不下一张 ⇒ `total_cap` / `no_cash`。
- 同一只已有未到期 put、持股、或未到期 call 时，不再叠加新的 put。

### 2.2 卖 put（v2，修订 2026-11-06；v1 原文见 §6）
- **候选** = 期限窗口 **30~50 天**内的**每个**到期日 × **不高于「接货价」**的行权价，须满足 §2.4，且有隐含波动率、
  **IV ÷ RV ≥ 1.0**（期权要比实际波动贵）。接货价缺省时为占位：开仓当天现价 × (1 − 10%)，记录里标 `accept_price_source = "placeholder"`。
- **选哪一张**：候选里**综合分 = 年化权利金 × (IV ÷ RV)** 最高的那张（同分——圆整到 1e-9——取更晚到期，再取更高行权价）。
  - 年化 = bid ÷ 行权价 × 365 ÷ 天数（现金担保口径）；IV = 该合约 CBOE 链的 `iv`；RV = 标的最近 30 个日对数收益（31 个**分红复权**收盘，yfinance，经 `yf_daily`；只用 ≤ min(开仓日, **取数那一刻**最近已收盘交易日) 的收盘，且窗口末根**必须恰是**这一场——缺了就是 `no_rv`，不把窗口往前挪一天顶替）的年化标准差，公式同 `vrp_signal.realized_vol_from_closes`；账本与 Alpha Bot 筛选页只经同一个入口 `sell_put_wheel.rv_asof`。
  - 算不出 RV ⇒ 这只当天不开（`no_rv`），**不猜、不拿别的波动率顶替**；合格档都没有 IV ⇒ `no_iv`；都低于门槛 ⇒ `iv_below_rv`。
  - 已知取舍（2026-11-06 用今天的链实测后与用户讨论过）：同一只里各档 IV/RV 差得很少，综合分多半由年化决定；IV 越近到期、越深虚值越高，
    这部分反映的是事件（财报）与偏斜，不一定是「贵」。之前一个月的数据里「溢价高 ⇒ 更赚」没有证据。
  - 30~50 天窗口里多半有 2~5 个到期日（含周度）；财报照卖、不避开（与 v1 同）——跨财报的到期日 IV 更高，会被综合分偏爱。
- **成交价** = bid（保守）。收到的权利金立即记入现金；担保现金不扣、只占额度。
- 每个交易日扫描后评估（财报前后照卖，不避开）。没开成的原因逐只记在 `meta.last_run.skipped`（原因码表 `SKIP_REASONS`）。

### 2.3 到期结算
- 到期日**当天及之前**不结（结算要那一场的定稿收盘，当晚恒取不到）；之后第一次运行起按**到期那一场**的官方收盘结算（`options_paper_leg._default_close`，自报场次，场次不符 ⇒ 延期，**绝不拿前一天的价顶替**）。
- put：收盘 < 行权价 ⇒ 被行权接货（现金 −行权价 × 100，持股 100，成本 = 行权价 − 已收权利金）；否则作废，权利金留下。
- call：收盘 > 行权价 ⇒ 被叫走（现金 + 行权价 × 100，一圈结束）；否则作废，持股不动，下一个交易日再卖。
- 美式提前行权不建模（实务里 put 提前被行权多见于深度价内 + 临近除息，call 提前被叫走多见于除息前）；这是已知偏乐观的地方。

### 2.4 「能卖」的合约
bid > 0、ask ≥ bid、(ask − bid) / mid ≤ 15%、未平仓量 ≥ 100。点差上限与跨式账本的口径一致（15%）；任何一条不满足就是对应原因码，不拿次好的顶替。put 从最高的合格档往下找（行权价更低 = 更符合「愿意买入」，只是权利金更少）。

### 2.5 多只同时能开
v2：按 §2.2 的**综合分**从高到低依次判额度（v1 是按年化权利金）。v3：排在前面的先装满能装的张数，后面的只用剩下的额度——额度集中在综合分最高的那只（**集中度是这条规则的直接后果**，不是 bug）。

### 2.6 被行权后的 covered call
- 每股成本底线 = 接货价 − 该次 put 权利金（**之后 call 的权利金不再降这条线**，免得越卖越低把亏损锁死）。
- （v3）**什么时候卖**：最近一个已收盘场次的收盘（与 RV 同一份分红复权日线、同一个截止场次，`rv_asof` 的 `close`）≥ 接货价 × (1 + 5%)；没涨够 ⇒ `not_risen`，取不到那一场收盘 ⇒ `no_close`，RV 算不出 ⇒ `no_rv`，都是当天不卖、次日再判。
- （v3）**卖哪一张**：与 §2.2 同一套——到期窗口 **30~50 天**内**每个**到期日 × 行权价 ≥ max(成本底线, 现价) 的合格 call，有 IV、IV ÷ RV ≥ 1.0，取**综合分 = 年化 × (IV ÷ RV)** 最高的那张；年化 = bid ÷ **现价** × 365 ÷ 天数（持股市值口径）；同分规则同 put；成交价 = bid。
  - 「行权价 ≥ 现价」是落口径时加的：价内 call 的权利金含内在价值，按年化排会专挑深度价内（等于按行权价把股票卖掉），不是「卖权利金」。
- 没有合格的 call ⇒ 当天不卖，原因记下，次日再试。
- 被叫走 ⇒ 这一圈结束；之后该标的回到 §2.2。**没有止损、没有止盈**：被行权是目的，不是亏损。

## 3. 记什么
- `lots.jsonl` 当前持仓（每只一条）· `events.jsonl` 卖出 / 作废 / 接货 / 卖 call / 作废 / 被叫走 · `equity_curve.jsonl` 每日净值与各标的收盘 · `meta.json` 现金与最近一次运行的跳过 / 延期 / 取不到链的原因。
- 盯市：未到期的腿按 mid（取不到合格双边报价就沿用上次 mark 并累计 `stale_days`），持股按当天 CBOE 链的标的价（盘后快照 = 收盘）。净值 = 现金 + 持股市值 − 未到期腿负债。

## 4. 对照基准（页面并排，**不是检验的零假设**）
1. **同价位限价买入**：每笔 put 开仓当天，在同一行权价挂 GTC 限价买入 100 股，到该 put 到期日之前收盘 ≤ 行权价即视为成交（只有收盘价，所以是保守的成交判据）。
2. **一直持有**：put 开仓当天收盘价买入 100 股，持有到该 put 到期日。
两条都不含权利金、不含 call。它们回答「卖 put 比直接买更好 / 更差多少」，不回答「该不该买这只」。

## 5. 失败必须看得见
整轮抛 / 全部标的取不到期权链 / 到期腿结算延期 ≥ 3 个日历日 / （v2）要开 put 的标的一只 RV 都没算出来（v3 起含要卖 call 的持股标的）⇒ `scan_timing.counters()["sell_put"]` → `alert_manager._check_sell_put` ⇒ **P2**（个别标的当天取不到链、结算延期 1~2 天是常态，不报）。账本写失败走 `ledger_io` 的源头登记（⇒ P2）。
