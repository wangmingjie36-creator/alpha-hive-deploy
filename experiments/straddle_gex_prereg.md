# 预注册：财报跨式 × GEX 政体（v1，2026-10-07 登记，v0.45.424）

机器可读常量与实现：`straddle_gex_prereg.py`（`PREREG`）。本文与代码不一致时以代码为准，并按 §8 记修订。

## 0. 起草人看过什么（盲化披露）

登记时 `gex_ctx` 字段**还不存在**（v0.45.424 才开始记录），任何一行信号都没有 GEX 影子记录，
所以起草时不可能看过「政体 × 结果」。看过的只有：跨式账本 7 笔（1 笔平仓，COST）、
`earnings_signals.jsonl` 里 2 个已结算事件（COST、MU）的实际 / 隐含比值。这些不影响下面任何选择。

## 1. 动机与证据等级

用户问「能不能用 Alpha Bot 的 gamma 数据让跨式策略做得更好」。可检验的最小命题：

> 信号日做市商处在**正 gamma** 政体的财报事件，实际事件波动 ÷ 隐含事件波动，比**负 gamma** 政体的更小。

| 依据 | 等级 | 说明 |
|---|---|---|
| 做市商净多 gamma → 随后实现波动更低 | B+ | 指数与个股均有、幅度中等；但证据多为**日常扩散**，不是财报跳空 |
| 财报跳空受做市商对冲影响 | 无直接证据 | 跳空发生在盘后 / 隔夜，对冲流来不及作用——这是本检验可能得零结果的先验理由 |
| 个股 OI 符号 | 弱 | 朴素口径（call +、put −）在个股上可能整个反了（Garleanu-Pedersen-Poteshman 2009） |

成立只说明「GEX 政体挑得出实际波动更小的事件」，是把它做成卖跨式过滤器的**必要条件，不是充分条件**。

## 2. 假设

- 度量：`y = ln( max(实际事件波动, 0.01%) ÷ 隐含事件波动 )`。实际 = `settle_signals` 回填的两日窗口 |涨跌|（`realized_abs_move_pct`）；
  隐含 = 代表行的 `implied_event_move_pct`。用对数让「贵一倍」与「便宜一半」对称；0.01% 下限只防 ln(0)。
- 统计量：`T = mean(y | positive_gex) − mean(y | negative_gex)`。
- H1（单侧）：T < 0。H0：同一财报周内，政体与 y 无关。

## 3. 独立单位与过滤（全部事前可知，不看结果）

1. 单位 = `(ticker, earnings_date)`，只看 `eligible` 行。
2. 代表行 = 该单位里**按信号日期最早**、`implied_event_move_pct > 0` 的行。被压成 0 的行（`event_move_floor_hit`）没有隐含事件波动，跳过（例：MU 2026-09-04~11）。
3. **先定代表行、再看它的 GEX**：代表行的 `gex_ctx` 不可用 ⇒ 整个单位不进检验，**不**往后找一条可用的顶上。可用 =
   `schema_version == 2`、`available is True`、`regime ∈ {positive_gex, negative_gex}`、`captured_on == as_of`
   （补跑旧日期时拿到的是另一天的链，不能冒充那天的环境）、`session_live is False`（收盘后记录，修订 1）。
4. 结果：同一事件任一合格行已回填实际波动即为已结算（`settle_signals` 对同一事件的所有合格行回填同一个值）。
5. 政体来源：`gex_ctx.regime`，即当天蒸馏结果里的 `gex_state`（全到期日视图，政体路由用的那份）。
   **不用** Alpha Bot 卖权选择器的 ≤45 天重定价零点：那是另一个冻结协议的输入，且那份协议把财报窗口整段排除。

## 4. 置换

- 分块 = 财报日所在的 ISO 周。只在同一周内打乱政体标签（保留每周各政体个数）。
- 为什么分块：财报扎堆在少数几周，政体又是全市场一起变；跨周打乱会把「那几周的行情」算成政体效应（本仓「横截面池化」教训）。
- 只有两种政体都出现的周（信息块）有贡献；全周同一政体的块不进统计。
- `n_perm = 5000`，`seed = 20261007`（Python `random.Random`，块按周字符串排序后依次消耗随机数，可复现）。
- `p = (1 + #{T_null ≤ T_obs}) / (1 + n_perm)`，并列算「≤」（保守）。

## 5. α 与判定

单个检验，单侧，α = 0.05。`p ≤ 0.05` ⇒ `reject_h0`，否则 `fail_to_reject_h0`。**只在就绪后跑一次**，不做中期偷看。

## 6. 就绪闸（同时满足）

| 条件 | 值 |
|---|---|
| 有效单位（GEX 可用且已结算） | ≥ 60 |
| 信息块里每个政体的单位数 | 各 ≥ 20 |
| 信息块（两种政体都出现的财报周） | ≥ 8 |

门槛是「置换分布不至于太抖」的启发式下限，**不是功效计算**。粗估（待验证）：30 只标的每年约 120 个财报事件，
能进窗口的约 100 个；两组各 20 个、且落在信息块里，大概要一年以上。够不着就是如实的「无法检验」，不是放宽闸门的理由。

## 7. 盲化（行为规则）

- 代码保证：`progress()` 只返回计数；`run_once()` 未就绪时拒绝运行；冻结前没有任何代码路径计算或显示两组的结果差。
- 信息论上盲不了：`gex_ctx` 与实际波动都在 `earnings_signals.jsonl` 里。**冻结之前从任何出口把某事件的 GEX 政体和它之后的
  实际波动 / 跨式盈亏拼在一起按政体比较 = 偷看 = 协议变更（§8）**。
- Alpha Bot「跨式账本」页因此不在持仓、平仓、校准图上显示任何一笔的 GEX；只显示影子记录进度（计数）。当天现算的
  GEX 水平照常显示（它是当天的环境，不是「历史政体 + 其后结果」）。
- 冻结：`/usr/local/bin/python3 straddle_gex_prereg.py --run-once`，结果写进 `<数据根>/options_paper_state/straddle_gex_prereg_result.json`
  （`os.link` 先到者赢，不覆盖）。之后只读这份。删改它 = 协议变更。

## 8. 什么算协议变更

改度量、统计量、置换方式、α、单位定义、代表行规则、GEX 可用性判据、就绪闸、`gex_ctx` 结构（`GEX_CTX_SCHEMA`），
或冻结前偷看（§7），都必须：在本文追加「修订 N」节（日期、版本、理由、改动前是否看过结果），把 `PREREG["version"]` 加一，
并声明截断（变更前的单位是否还进检验；默认不进）。修 bug（实现与本文不符）不算协议变更，但同样要记修订并说明受影响的行。

## 9. 已知局限

- 隐含事件波动扣扩散用的是 30 日实现波动（`earnings_vol_signal` 模块头），rv 含别的跳空时会把隐含压低、甚至压成 0；
- 财报时段（盘前 / 盘后）未观测，两日窗口是刻意的安全选择；
- 政体是**信号日**收盘后的状态，不是财报前一刻的；
- OI 是 t−1 的，个股 OI 符号可能整个反了（§1）；
- 只有 30 只标的，同一周内的事件彼此相关（分块只处理了「周」这一层）。

## 修订 1（2026-10-08，v0.45.428，`PREREG["version"]` 1 → 2，`GEX_CTX_SCHEMA` 1 → 2）

- **理由（二次检查发现的 bug，实现与 §9 不符）**：§9 写明政体是「信号日收盘后的状态」，但 v1 的影子记录不记时刻，
  同日重跑又是「当天第一次可得记录为准」——有人盘中手动跑日报（卖权预注册 §3 记过这种情况确实发生）就会把**盘中**
  的 GEX 锁成当天政体，收盘后的生产扫描替换不掉；检验也分不出来。
- **改动**：`gex_ctx` 加 `captured_at`（美东时刻）与 `session_live`（记录时是否在常规交易时段，按交易日历与提前收盘日判）；
  §3 第 3 条的「可用」加一条：`session_live is False`（盘中记录 → `gex_unusable:intraday_capture`，判不了 → `session_unknown`）；
  同日重跑改为「当天第一次**收盘后**的可得记录为准」，盘中的旧记录让位给收盘后的新记录。
- **改动前是否看过结果**：没有——修订时 `gex_ctx` 还一行都没有记录（第一轮记录是 2026-10-08 14:00 PT 的扫描）。
- **截断**：`schema_version` 不是 2 的记录一律不进检验（若 v0.45.424 的代码赶在本修订部署前跑过一轮，那一轮的记录在此被截掉）。

## 10. 运行

- 每日扫描：`alpha_hive_daily_report._post_scan_notify` 调 `earnings_vol_signal.scan(..., gex_fn=...)` 记录影子字段；
  `settle_signals` 回填实际波动。都不读 `gex_ctx` 做判断（`tests/test_straddle_gex_shadow.py`）。
- 就绪度：`/usr/local/bin/python3 straddle_gex_prereg.py`（只读）；Alpha Bot「跨式账本」页底部同一份计数。
