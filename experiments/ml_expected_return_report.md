# ML 预期收益结构性看多偏斜 —— 诊断与修复

**日期**：2026-08-16 · **版本**：v0.44.1
**复现**：`/usr/local/bin/python3 experiments/ml_expected_return_replay.py`

---

## 起因

`tests/test_distribution_invariants.py` 报出 `RivalBeeVanguard` 近 12 个扫描日
**95.2% 看多**（bullish 180/189），是所有非看空蜂里最偏的，且不在任何已知问题清单里。

## 根因（三层，逐层实测）

### 第 1 层：`expected_7d` 结构性恒正

`ml_predictor.py` 旧公式：

```python
catalyst_bonus = {"A+":25,"A":20,"B+":15,"B":10,"C":5}.get(quality, 10)  # 恒 ≥5
crowding_penalty = clamp(crowding, 0, 100) * 0.1                         # 恒 ≤10
expected_7d = catalyst_bonus + momentum_bonus - crowding_penalty
```

`catalyst_bonus` 永不为负、`crowding_penalty` 上限 10 ⇒ **唯一能为负的项只有动量**。
要让"预期收益"转负需 5 日跌超 5%（催化剂 A+ 时需跌超 25%）。

**量纲也是错的**：`catalyst_bonus` 是催化剂**质量等级**（5~25 的"分"），却直接与
`momentum_5d`（**百分点**）相加当预期收益。于是"B 级催化剂" = +10 个百分点的
7 日预期收益。这与 ChronosBee「权重表只编码影响多大、不编码影响好坏」同族。

### 第 2 层：`rival_bee.py` 把特征写死成常量

```python
crowding_score=50.0,      # 硬编码 —— 蜂群明明算了真实拥挤度
catalyst_quality="B+",    # 硬编码 → catalyst_bonus 恒为 15
iv_rank=50.0,             # 硬编码
put_call_ratio=1.0,       # 硬编码
market_sentiment=_mom_ml * 5,   # 由动量派生，不是真实情绪
```

代入旧公式得闭式 **`expected_7d = 8.0 + 0.8 × momentum_5d`**，在 1057 个配对样本上
**零反例**。验算：动量中位数 0 → +8.00%（实测中位数 +8.00%）；动量最小 −26.04 →
−12.83%（实测最小值 −12.83）。

**生产里所谓的"ML 预期收益"就是一个截距 +8% 的一元线性式。**

⚠️ 这一层**本次未修**。RivalBee 在 Phase-1 并行，`catalyst_quality`（ChronosBee 域）、
`iv_rank`/`put_call_ratio`（OracleBee 域）在那时点确实拿不到，要改需动阶段结构。
见下方「未做」。

### 第 3 层：`probability` 的中性点全在 0.5 之上

`ml_predictor.py` 旧实现的分项：

| 特征 | 旧形式 | 区间 | 中性点 |
|---|---|---|---|
| crowding | `1.0 − x*0.3` | [0.7, 1.0] | 0.85 |
| iv_rank | `1.0 − x*0.3` | [0.7, 1.0] | 0.85 |
| put_call_ratio | `1.0 − x*0.4` | [0.6, 1.0] | 0.80 |
| volatility | `1.0 − x*0.5` | [0.5, 1.0] | 0.75 |
| momentum / sentiment / agent_agreement / direction_encoded | `0.3 + x*0.7` | [0.3, 1.0] | 0.65 |

按默认权重算出**结构性地板 0.3610**，与实测最小值 **0.3500** 吻合。
实测 `ml.probability` **99.6% > 0.5**，中位数 0.5728。向下空间 0.139 vs 向上 0.45
——**不对称约 3.2 倍**，它无法表达"强烈看空"。

代码注释声称「每个分项必须在 [0,1] 范围内 …… 加权和自然在 [0,1]」——范围确实对，
但**中性点不在 0.5**，这是注释没说、也没人验过的那一半。

### 附带：三处重复 + 一处更露骨的钳制

- 公式在 `SimpleMLModel:390` / `SGDMLModel:672` / `HGBModel:1197` **逐字重复三份**，
  docstring 还写着"公式与 SimpleMLModel 完全一致"——那种一致性靠人肉维护。
  **换模型（Simple→SGD→HGB）对本问题完全无效**，训练只影响 `probability`。
- `ml_predictor_extended.SimpleMLModel`（`ml_predictor` 导入失败时的降级实现）
  用 `max(0, ...)` 让负值**结构性不可能**，且期限缩放是 0.3/**0.7**/1.2，
  与主实现的 0.3/**0.8**/1.2 悄悄不一致。

---

## 修法

1. **催化剂质量只调幅度不调方向**：改为无量纲乘数
   `{"A+":1.5,"A":1.3,"B+":1.0,"B":0.9,"C":0.7}`，不参与符号。
2. **拥挤度以中性 50 为中心**：`tilt = (crowding−50)/50 × 5.0`，可正可负。
3. **统一量纲**：全部项为百分点。⇒ **无信号时预期收益为 0，而不是 +8%。**
4. **单一真相**：三处重复合并为模块级 `expected_returns()`，三个模型类共同委托。
5. **`probability` 居中**：新增 `centered_feature(x, influence, inverse)`，
   **保留每项原有的影响力系数**，只把中性点搬回 0.5。因此不是靠削弱某个特征来
   消除偏斜——特征间相对影响力不变。`influence=1.0` 时等价恒等映射，
   所以本来就居中的 catalyst / final_score / odds_score / risk_adj_score 四项数值不变。
6. **降级实现镜像主实现**，去掉 `max(0,...)`，期限缩放对齐。
   重复是结构性强制的（它存在的前提就是主实现不可用），
   用 `TestFallbackMirrorsPrimary` 断言两份数值一致来兜住。
7. **`rival_bee.py:121-126` 的 EPS 单向棘轮**：`positive` 会把 neutral 翻成 bullish，
   `negative` 缺对应分支。补齐。**必须与本次同时落地**——修好 expected_returns 后
   neutral 会真的出现（动量为 0 的样本在近 12 个扫描日占 63.7%），
   这个棘轮就会接替成为主要偏斜源。
8. **缺失值处理**：`momentum_5d` 为 None/NaN/非数值时按 0（无观点）。
   旧实现 `momentum_bonus = data.momentum_5d` 对 None 会直接 TypeError。

# v0.44.2 追加：传入真实拥挤度，并否决把它做成收益项

## 做了什么

`rival_bee.py` 不再把 `crowding_score` 写死为 50.0，改为走 ScoutBee / GuardBee
**已在用的同一条路**取真实值：

```python
_detector = CrowdingDetector(ticker)
_metrics = get_real_crowding_metrics(ticker, stock, self.board)
_crowding, _ = _detector.calculate_crowding_score(_metrics)
```

**成本可忽略**：内部两个网络调用都有缓存（social TTL 3600s / short interest
TTL 86400s），`stock` 由本蜂已取的 `_get_stock_data` 传入。ScoutBee 先跑时是缓存
命中；最坏情况（与 ScoutBee 并行同时未命中）每标的多一次抓取。
GuardBee 在 Phase-1.5，必然命中。

只补这一个特征的原因：`catalyst_quality` 属 ChronosBee 域、
`iv_rank`/`put_call_ratio` 属 OracleBee 域，而 RivalBee 在 **Phase-1 并行**运行
—— 那个时点它们还没产出。要补需动阶段结构。

## 过程中发现的陷阱：中性点是猜的

v0.44.1 把倾斜的中性点设为 **50**（量表中点）。而实测 `crowding.score`（n=1057）：

| min | p10 | p25 | **中位** | p75 | p90 | max | ≥50 占比 |
|---|---|---|---|---|---|---|---|
| 10.55 | 13.40 | 17.43 | **23.30** | 32.89 | 43.23 | 68.56 | **4.6%** |

检测器自己的档位是 `<30` 低 / `30~60` 中 / `≥60` 高，即设计者心里的中性带中心
约 45 —— **也与实测差得远**，95% 以上样本落在"低拥挤度"档。

**若直接把真实值传入而不重标中性点**：95.4% 的样本会被判"不拥挤 → 加分"，
中位 tilt = −2.67pp ⇒ **重新引入 +2.67pp 的系统性正偏**，把 v0.44.1 修掉的东西
部分抵消回去。所以「传真实值」和「重标中性点」必须同时做——
**这个改动不是"低风险局部改进"，除非两件一起做。**

## 但最终否决了倾斜项本身

重标后（中心 23.30、稳健半宽 14.92、钳 ±5pp）全样本 tilt 中位数 = 0.000pp，
偏差改善到 **+0.19pp**。看着更好，但用现成的四口径工具
（`signal_archive.py --analyze`，噪音地板 |IC|=0.076、需 ≥3/4）复核后否决：

| 信号 | 样本 | 日度IC | t | 通过口径 | 判定 |
|---|---|---|---|---|---|
| `crowding.score`（连续） | 669 | **+0.1122** | +2.48 | **1/4** | 🟡 口径不足 |
| `crowding.signal` | 669 | −0.1128 | −2.49 | 1/4 | 🟡 口径不足 |
| `crowding.adj_factor`（分档） | 669 | −0.1117 | −2.81 | 3/4 | 🟢 候选 **⚠️稀疏** |

三条否决理由：

1. **方向未确立，且现有证据与设计意图相反。** 三个口径都指向
   「**高拥挤 → 收益更高**」，而检测器 `get_adjustment_factor` 对高拥挤打 30% 折。
   连续版**不达标**（1/4）；达标版（3/4）只有 6 个取值、被工具自己标 ⚠️稀疏，
   命中 MEMORY 记载的「`distinct_ratio<0.25` → rank-IC 失真」陷阱。
   ⇒ 不该据此翻转符号，也不该继续用一个与现有证据相反的符号。
2. **三重计数。** 拥挤度已是 `predict_probability` 里**权重最大的特征**
   （`crowding: 0.18`），又经 `adj_factor` 作用于综合分。
3. **它不是收益预测量。** 拥挤度是容量/风险概念，已确立的用法是乘性折扣；
   折成"多少个百分点的预期收益"需要凭空定标度。

**代价说清**：否决后偏差从 +0.19pp 回到 +1.06pp。但那 +0.19 是**巧合**——
倾斜的均值恰好抵消了动量带来的正偏，不是因为符号对。
**宁要 +1.06pp 的可辩护公式，不要 +0.19pp 的不可辩护公式。**

## 未做（需决策）

2. **拥挤度的真实方向**值得单独查：三个口径一致指向"高拥挤 → 收益更高"，

## 已知限制

- 回放用的是 `rival_bee` 硬编码特征下的闭式，因此结论只覆盖生产路径；
  若将来传入真实特征，需重跑本脚本。
- 期限缩放（0.3/0.8/1.2）未改，三个期限仍是同一个量的缩放、符号恒同。
  下游 `avg_ret = (expected_7d + expected_30d)/2` 等于 `expected_7d × 1.0`，
  看似平均两个期限实则没有——有测试钉住这一事实，供将来重构参考。
