## 0. 结论

**唯一有实质证据的是 `sentiment`（情绪维度 / BuzzBeeWhisper）**，IC = **+0.170**，
不重叠周 t = **+3.16**，三分位多空毛价差 **+3.98%/周**。

**而系统实际下决策用的 `final_score` 是 IC +0.025、t=+0.46、p=0.65——完全无预测力。**
聚合过程把唯一有效的输入稀释掉了。这是本次普查最有行动价值的一条。

⚠️ 未过 53 信号的严格 Bonferroni（p=0.082）。N_eff 仅 21–23 周。**尚不足以据此改交易规则。**

## 1. 为什么要重扫

`ic_diagnostics.py` 在 v0.45.17 前的**所有口径都建立在被截断的收益上**：
`return_t7` 是路径依赖离场收益；`price_t7` 自 2026-05 起等于 `exit_price`，同样截断
（v0.42.7 曾察觉截断问题并加了 `price` 口径，但选错了列）。
真正干净的是 v0.45.17 新增的 `close_t7`。

换口径后，5 个维度里谁是主角**直接反转**：

| 维度 | 污染口径（price） | 干净口径（close） |
|---|---|---|
| `risk_adj` | **四口径全过** t=−3.02 | 三口径过 t=−2.50，jackknife 失效 |
| `sentiment` | **无口径通过** t=+1.97 | **三口径过 t=+3.16，Bonf(5维) p=0.008** |

**旧的维度 IC 排名不可再引用。**

## 3. sentiment 通过的四道排除检验

这个信号大到可疑（+3.98%/周），所以逐条查过confound：

1. **前视偏差**：`dimension_scores` 由 `save_predictions` 在**扫描时**落库，事后不更新；
   扫描 14:00 PDT 在美股收盘（13:00 PDT）之后，`price_at_predict` 即当日收盘价。
   收益从该收盘价起算 → 结构上无前视。
2. **是不是动量的马甲**：`price.momentum_5d` 自身 **IC=+0.008、t=+0.12，完全为零**。
   sentiment 携带的是动量没有的信息。
3. **是不是被少数几周驱动**：剔除 |IC| 最大的 3 周后仍有 t=**+2.25**；
   价差中位数 +4.32% 贴近均值 +3.98%；最差周仅 −4.07%。
4. **regime 依赖**：上涨期 +0.0935、下跌震荡期 +0.1186，**符号一致**
   （对比 `catalyst` 上涨 +0.131 / 下跌 −0.148，那种才是相消假象）。

另有旁证：同族的 `agent.BuzzBeeWhisper.score`(+0.145) 与 `sentiment.pct`(+0.115)
方向一致——是连贯的信号族，不是孤立的噪音峰。

## 4. 保留意见（不得省略）

- **未过严格 Bonferroni**：53 个信号里 0 个过 α=0.05/53。sentiment 的 p=0.0016 ×53 = 0.082。
  唯一能说它过的口径，是把它当作 **5 个预设维度之一**（×5 → p=0.008）——
  这在统计上可辩护（维度是设计时就定好的，不是事后挑的），但**不如全局校正保守**。
- **N_eff 仅 21–23 周**，样本方差自身相对标准误 ≈ 32%。
- **+3.98%/周作为可持续 edge 不现实**。21 周的样本内估计天然上偏，
  真实幅度预期显著更低，样本外衰减应按"腰斩起步"预期。
- **毛口径**：未扣佣金/点差/冲击成本；做空腿未验证可借券与费率。
- IC 只衡量排序能力，不等于扣成本后可盈利。

## 5. 下一步（按价值排序）

1. **别急着改权重**。先让 N_eff 长到 ~40 周再看 sentiment 是否还在。
   改权重须走 `weekly_optimizer` 既有闸（v0.44.0 起只读诊断）。
2. **查 final_score 为什么把信号聚合没了**——这是当前最反常的一条：
   一个 IC=+0.17 的输入，经过 7 蜂加权后变成 IC=+0.025。
   若是权重问题则可修；若是其余 6 蜂的噪音淹没了它，则该考虑降权而非等权。
3. **重跑所有依赖旧 IC 的历史结论**。`ic_diagnostics` 现已默认 `close` 口径，
   但此前基于 `price`/`path` 得出的维度排名、权重讨论都应视为待复核。
4. `crowding.adj_factor` 与 `price.volatility_20d` 值得单独跟踪
   （IC 分别 −0.138 / −0.196，regime 一致），但剔极端后均失效，暂不可用。
