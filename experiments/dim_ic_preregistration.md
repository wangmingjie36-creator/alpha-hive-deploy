## 0. 为什么需要这份协议

同一份数据上，「sentiment 是唯一可交易信号」对应的 p 值，随三个**研究者自由度**在 0.002 与 0.6 之间摆动：

| 自由度 | 实测摆幅（2026-09-18 快照，旧世代为主，探索性） |
|---|---|
| 每周取哪一天 | 固定周一 t=+3.97，周四 t=−0.54；改成周内全部交易日均值后 ×5 的 p 由 0.008 变 0.247 |
| 检验族多大 | 同一个 t：5 维族 p=0.008，69 信号族 p=0.11 |
| 正态还是 t | 同 n 下 p 约差 3 倍 |

这些选择只要在看完数据之后再做，p 值就没有意义。本协议在**当前世代数据被看到之前**把它们写死。
取证细节：auto-memory `alpha-hive-t-vs-normal-p.md`、`alpha-hive-tradeable-signal.md`。

## 1. 起草人看过什么（盲化披露）

- **看过**：截至 2026-09-18 的**全史池化**估计（26 个不重叠周，其中 sentiment 当前世代约 2–3 周混在里面）；
  旧世代（各维度世代起点之前）的周度 IC 噪音参数（σ、lag-1 自相关）。
- **没看过**：任何**只用当前世代**算出的 IC、t、p、收益。起草期间对当前世代只数了日期、周数、横截面宽度。
- **看完数据才定的选择**：估计量「周内全部交易日均值」是看过池化结果后提出的（它在旧数据上让 sentiment 变弱、
  risk_adj 变强）。选择理由是统计性质（用上全部数据、没有任意挑日），不是结果好看。
  为此，**样本窗口从登记后下一周开始**（§3），把已被池化看过的那几周排除在外。

## 2. 假设

**固定序列**（顺序事先写死；前一个被拒绝才检验下一个，每个都用满该检视点的 α）：

| 编号 | 假设 | 对象 | 为什么排在这里 |
|---|---|---|---|
| **H1**（主） | sentiment 维度的横截面 rank-IC ≠ 0 | `dimension_scores.sentiment`（= BuzzBeeWhisper 的 `score`） | 「唯一可交易信号」的说法、09-09 的权重改动都押在它上面 |
| **H2** | 加权合成的横截面 rank-IC ≠ 0 | Σ wᵢ·dimᵢ，wᵢ **冻结为登记时的** `config.EVALUATION_WEIGHTS`（catalyst 0.332 / sentiment 0.325 / odds 0.343 / signal 0 / risk_adj 0），**Queen 调整之前** | 真正决定排序的对象；排在 H1 后面，是因为只有 sentiment 带信号时它会被稀释、功效更低 |

**描述项**（任何结果都**不触发动作**）：其余 4 个维度（signal / catalyst / odds / risk_adj）各自的 IC、CI、
Holm 校正后的 p（族 = 4）。描述项里看起来显著的，只能作为**下一轮登记**的假设来源。

两侧检验：显著为负同样有行动含义（§7）。

## 3. 样本

| 项 | 规定 |
|---|---|
| 窗口起点 | `FORWARD_START = 2026-09-28`（登记后下一个 ISO 周的周一，2026-W40）。之前的数据一律不进检验 |
| 日期 | NYSE 交易日（周一至周五且当天有扫描）；周末扫描排除 |
| 结果变量 | **`close_t7 / price_at_predict − 1`**。⚠️ **不许用 `price_t7`**：自 2026-05 起它 100% 等于 `exit_price`（带止损/止盈截断），8–9 月约 40% 的行与 `close_t7` 不同。`signal_archive.load_panel()` 目前正用着 `price_t7`（另案处理），**不能**拿 `analyze()` 当本协议的执行器。也不许用 `return_t7`（路径依赖） |
| 排除 | `signal_archive.QUARANTINE` 登记的已知坏行；此外**不按数据质量再剔除**（意向性分析：降级日照算，这就是系统实际的样子） |
| 横截面 | 某日某假设的有效标的数 ≥ **20**，且分数至少 2 个不同取值；否则该日对该假设无效 |
| H2 的标的 | 5 个维度分齐全的标的 |

## 4. 估计量与检验统计量

1. **日度**：当日横截面 Spearman rank-IC（并列取平均秩）。
2. **周度**：同一 ISO 周内全部有效日的日度 IC **等权平均**，得到一个周值。有 ≥1 个有效日的周算一个**合格周**。
3. **统计量**：t = 周值均值 / SE，SE 取 **Newey-West，Bartlett 核，lag = 1**。
   理由：T+7 收益窗口跨到下一周，相邻周值正相关（旧世代实测 lag-1 自相关 +0.01 ~ +0.40）。
4. **参考分布**：t(G − 1)，G = 合格周数。不用正态近似。
5. 同时报告：周值均值（IC）、95% CI（同一 SE、同一 t 临界值）、朴素 iid t（仅作对照）。

**明确不用**：「每周第一个可用日」（`ic_diagnostics.subsample_non_overlapping`）作为检验统计量；
`passed_methods` 的「≥3/4 口径 |t|≥2.0」判定；全信号 Bonferroni。

## 5. 检视点与 α

G 按 **H1 的合格周数**计（H2 用检视当时自己已有的全部合格周）。

| 检视 | 触发 | 两侧 α（每个假设） | 预计时间（每周都有扫描时；漏扫只会推后） |
|---|---|---|---|
| 中检 | H1 合格周 G ≥ 26，且这些周的 T+7 全部结算 | 0.01 | ≈ 2027-04-01 |
| 终检 | G ≥ 52 | 0.04 | ≈ 2027-09-30 |

中检拒绝的假设不再在终检重复检验；中检未拒绝的在终检用 0.04 重检。
α 在检视点间按 Bonferroni 拆分（0.01 + 0.04），在假设间用固定序列 ⇒ 整体 FWER ≤ 0.05（保守）。

## 6. 世代边界落在协议期内

**原则：检验的是登记时的定义。**

- 在 `FORWARD_START` 之后，只要 `ic_rerun_readiness._COHORT_HISTORY` 新增的边界经 `signal_archive.generation_boundaries()`
  的影响面闭包触及某假设的对象（H1：`agent.BuzzBeeWhisper.score`；H2：Chronos / Buzz / Oracle 三只蜂的 `score`，
  或 `config.EVALUATION_WEIGHTS` 偏离 §2 的冻结值），该假设的序列就在**边界日期截断**，此后的样本不再计入。
- 检视时截断后的合格周不足该检视点要求 ⇒ 该假设判为「**无法检验（定义已变）**」。
  固定序列按「未拒绝」处理，后面的假设不再检验。
- **不池化**跨边界的样本，也不自动重置时钟（重置 = 事实上的新协议，要重新登记）。
- **代价**：协议期内改 BuzzBee 的评分逻辑就会终止 H1。改动前要知道这笔账：约一年的等待会作废。
  本协议**不冻结** BuzzBee（不加阻止改动的守卫）——改不改由当时决定，只是代价事先透明。

## 7. 结果与动作（事先写死）

| 结果 | 动作 |
|---|---|
| H1 显著为正 | 「sentiment 有预测力」升级为「已确认（预注册）」。**权重调整的幅度另行决策**，本协议不定幅度 |
| H1 显著为负 | sentiment 权重进复审，默认置 0 并排查原因；**不自动取反** |
| H1 终检未显著 | 撤回「唯一可交易信号」的说法，改为「未证实」。现行权重**不因此自动改**（09-09 的决定本来就不以确认性证据为前提），但此后以 sentiment IC 为理由的加权提案不再有依据 |
| H2 显著为正 / 为负 / 未显著 | 同上三行，对象换成现行加权方案：为负 ⇒ 权重方案进复审 |
| 无法检验 | 报告「未能检验」，不做任何推断；要继续就重新登记 |
| 描述项 | 只报告，不行动 |

## 8. 盲化

- 检视点之前，执行器（P2）的**返回值在数据结构上不含**效应量（IC、t、p、CI、收益），
  只含进度：各假设的合格周数、是否被截断、下一个检视点还差几周。做法照 F&G 前瞻检验 v0.45.300 / v0.45.308（白名单键）。
- 进度挂在 `ic_rerun_readiness --quiet` 那一行（与共振、F&G 两个前瞻检验并列）。
- 检视点之前**不许**为了「看看趋势」跑任何只用当前世代、落在 `FORWARD_START` 之后的 IC。
  其他工具（`analyze()`、`ic_diagnostics`）照常可用，但它们的输出**不构成本协议的证据**。

## 9. 功效（诚实数字）

H1，有效 σ_week ≈ 0.230（旧世代 sentiment σ 0.221 × NW 膨胀 1.04），两侧：

| 真实 IC | 中检 G=26（α=.01） | 终检 G=52（α=.04） |
|---|---|---|
| 0.050 | 6% | 30% |
| 0.090 | 24% | 76% |
| 0.135 | 59% | 98% |
| 0.180 | 87% | 100% |

**读法**：真实 IC 在 0.09 量级时，要约一年才大概率给出结论；在 0.05 量级时，这个协议基本判不出来，
终检结果多半是「未显著」——那也是一个结论：「在这个系统的样本速度下，这点效应不值得押注」。
作为对照：5 维 Holm 全族的设计在 IC=0.09 时要约 102 周才有 80% 功效，这是本协议选单一主假设的原因。
H2 的功效未估：旧世代多为 10 只标的时期，满足宽度 ≥20 的周只有 2 个，噪音估不出来。

## 11. 修改规则

登记后改动本文件任何一条规则都必须在 CHANGELOG 标「**事后**」并写理由；
检视点之前的纯实现修正（不改规则、不改数字）标「事前实现对齐」。
`experiments/dim_ic_protocol.py` 的常量与本文件是同一份登记的两种写法，改一处必须同步改另一处，测试会红。

## 12. P2 执行器必须做到（验收清单）

1. 常量全部从 `experiments/dim_ic_protocol.py` 读，不另抄一份。
2. p 值用 t(G−1)，SE 用 NW(1)；不调用 `ic_diagnostics.normal_two_sided_p`。
3. 结果变量读 `close_t7`；任何读 `price_t7` / `return_t7` 的代码路径都算违规（要有测试会红）。
4. 截断：H1/H2 各自按 §6 求截断日；H2 另需识别 `config.EVALUATION_WEIGHTS` 偏离冻结值的日期（git 历史或 `weight_history.jsonl`，实现时择一并写明）。
5. 盲化在返回值的数据结构上（白名单键），检视点前不含效应量。
6. 进度行接进 `ic_rerun_readiness`；失败渲染成可见的一行，不吞（同 F&G 前瞻检验的挂法）。
7. 判别测试：构造 t 落在 [z 临界, t 临界) 之间的周序列，确认它判「不显著」。
