# LLM 影子 A/B 预注册（v0.45.555，2026-10-19，**看数据之前**写的）

**问题**：同一天、同一份输入下，开着 LLM（Opus 5.5 低 effort + 精简 Oracle 提示词）算出来的方向，T+7 命中率是否与纯规则不同？

**为什么前瞻**：历史重跑不可行——输入不是当时的快照；模型知识截止 2026-06，对 3~6 月行情有前视偏差。
历史上网站总收益对早期样本极敏感（含全部样本 −0.99%，剔除 ≤04-17 的 280 行 −10.83%），但早期段混着行情、
CRCL 02-26 一笔 +28%、04-26 ScoutBee 重平衡，**不能**据此说 LLM 有效。

## 两条臂
- **LLM 臂**：`llm_shadow_scan.py --run` 的 `final_score` / `direction`（当前代：Sonnet 5.5 + 精简 Oracle 提示词，蜂层面与 Queen 层面的 LLM 都开；代的定义见「代」一节）。
- **规则臂**：**生产当天自己的规则引擎结果**——生产库 `predictions` 里同日同标的的 `final_score` / `direction`（生产永远 `--no-llm`）。
  生产收盘后 14:00 才跑，影子扫描紧随其后：价格静止，影子根的 `cache/` 也已被生产更新过，两边输入一致。
- ⚠️ 影子 `swarm_results` 里的 `rule_score` **不是**规则臂。它由各蜂的维度分算出，而蜂在 LLM 模式下已把 LLM 混进自己的分数
  （OracleBee 以 0.6 权重混入 `smart_money_score` 并可改写方向）；Queen 的 LLM 只是再加一层。
  它只用于描述性分解（Queen 层 = `final − rule_score`；蜂层 ≈ `rule_score − 生产 final`，含两次扫描的输入噪声），不参与检验。

## 入选
- 只用 `quality.healthy == true` 的 LLM 日（有预算 / 定价拒绝、LLM 一次没调成、截断率 / JSON 失败率 / **请求失败率**（发出请求却没拿到响应，v0.45.560 增）> 10%、
  蒸馏走 LLM 的标的 < 80% 的日子**整天剔除**——那一天的「LLM 臂」大部分是规则臂）。子进程中途崩溃只留占位记录的日子同样不健康。
  （第 560 版增的这条请求失败率与占位规则是**在任何一次真跑之前**加的，没有数据被它改过入选。）
- 标的日要 LLM 臂的最终分与方向、规则臂（生产）的最终分与方向都齐全；T+7 结果取生产库同日同标的的 `price_at_predict` 与 `close_t7`，
  缺价 / 未到期 / 生产里没有该日该标的，都不入检验（缺了多少如实报出）。

## 主检验（唯一）
- 只看**两臂方向不同**的标的日（方向相同的对差异无贡献）。判对错用仓库既有的 `outcome_utils.determine_outcome_triplet`；
  任一臂「模糊」的剔除，不当作两边都错。
- 统计量：「只有 LLM 对」b 与「只有规则对」c；**McNemar 精确检验，双侧**，α = 0.05。
- **不做**多重比较之外的任何子集挖掘（按标的 / 按月 / 按分数段拆分都不是本协议的检验，只能作探索、不能下结论）。

## 样本量门槛（没到之前报告工具**不计算**命中率）
- 健康的 LLM 日 ≥ **20**；
- 「方向不一致且 T+7 已出」的标的日 ≥ **60**。

两条同时满足才计算并报告。门槛先于数据定下，不随结果调整。
功效说明：b 与 c 在 H0 下各 1/2，n = 60 时只能检出较大的差（例如 b:c ≈ 40:20 时 p ≈ 0.01）；
小的真实差异需要更多天——**样本不够时的正确结论是「还没有证据」，不是「没有差别」**。

## 停止与改动
- 提示词 / 模型 / `max_tokens` / 精简规则任何一项改动 ⇒ 新的一代，**重新计数**，旧样本不与新样本合并。
- 每日硬上限 $3；覆盖名单逐日记在状态文件里，检验只用实际覆盖到的标的日。

## 代（generation）
状态文件带 `generation` 字段；`llm_shadow_report` 只数**最新一代**的天，旧代的天如实报出个数、不与新代合并。
- **g1（`legacy:claude-opus-5-5`，v0.45.555）**：Opus 5.5、`effort=low`、22/30 按日期轮换、`max_tokens = max(请求×3, 请求+1024)`、
  Oracle 提示词按 `_compact_options_for_llm` 精简（溢价前 8 ∪ 成交量前 5 ∪ vol/OI 前 5）。**只跑了 2026-10-21 一天**
  （22 只、$2.74、健康），不入当前计数。
- **g2（`g2-sonnet-5-5`，v0.45.592，2026-10-22 起）**：模型换 `claude-sonnet-5-5`（思考 `between_tools`，无 `effort`）、
  **30 只全跑**（不再轮换）、**影子里关掉「历史类比」**（v0.45.594，见下方局限 5）、**输出上限放宽为 `max(请求×3, 请求+2048)`**（v0.45.595，g1 是 +1024；原因见局限 6）、Oracle 精简规则同 g1。换代原因：用户 2026-10-22 定，更便宜（≈ 一半单价），
  使 30 只都进得了每日 $3 上限。每日由 launchd 在生产扫描写完后自动跑（`llm_shadow_daily.py`），见该文件 docstring。
- ⚠️ 换模型本身就是处理变化：g2 的结论**只对 Sonnet 5.5** 成立，不外推到 Opus。
- 报告同时列出「生产有扫描、这一代却没有 LLM 记录的日子」——自动任务没跑成会让样本悄悄变少，不能靠看日志发现。
- **一天只许付费跑一次**：$3 上限在进程内计，跨进程靠 `shadow_status/<日期>.json` 是否存在来挡（v0.45.560）；
  `--control` 写 `<日期>.control.json`，与付费记录分文件，互不覆盖。

## 已知局限（先写下，免得事后当成发现）
1. 两条臂**共享**取数、ML、政体权重等非 LLM 部分；比较的是「LLM 开 / 关」，而不是别的差异。两次扫描之间的输入噪声（新闻、
   取数时点）会被算进差异里——影子 `--control`（LLM 关）与生产的逐只分差就是这份噪声的度量，**第一次真跑之前先跑一次**，
   并在 `llm_shadow_report` 的描述里和 LLM 臂的分差对照。
2. 同一提示词重复跑，LLM 输出有随机性（最小样本里分数 / 方向一致、`signal_type` 文案三次互异）。
3. 精简后的两条大 Oracle 提示词从未与原版对照过。
4. （g1）每日硬上限 $3 只够约 22/30 只，覆盖名单按日轮换；g2 起 30 只全跑，该局限不再适用。
5. **历史类比成分（g1 有、g2 起关闭）**：LLM 模式下，当天分数前 3 的标的若影子 Chroma 命中 ≥5 条，会多一次 LLM「历史类比」并给
   `final_score` 加减最多 0.5（**只改分、不改方向**）。g1 唯一的一天 AMZN 触发过（−0.15，模型自己说「无实际回报数据可验证」，
   类比对象是前一天影子 control 存进 Chroma 的记录）。它是 `agent_memory` 表的唯一读者，该表回填历史有「后一轮覆盖前一轮」
   的已知缺陷（v0.45.527）。用户 2026-10-22 定：影子里只关这一个读者（`llm_shadow_scan.disable_historical_analogy`，仅在
   真实扫描入口里打补丁，生产不碰），表和写入都不动。关闭若失效（函数改名 / 补丁没生效），状态里 `analogy_fired` 会记下，
   当天判不健康、整天不入比较。
6. **Sonnet 5.5 的截断**：10-19 试跑里 Sonnet 在**未放宽** `max_tokens` 时 11/18 次截断（Haiku 18/18）。真因（v0.45.595 查明）：
   **调用点上限（256 / 300 / 400 / 800）小于模型的自然输出长度**，与思考无关（Sonnet 回复块全是 text）；Opus 放宽后实测自然长度——
   蜂的单次评估 150~440 token，BearBee 空头论述 1096 / 1215、Queen 蒸馏 1105。g2 的 Sonnet 上限因此放宽到 `+2048`
   （最长 1215 对 2448，约 2×）。**放宽后的真实截断率仍未实测**，要看 g2 头几天的 `truncation_rate`（> 10% 整天不入比较）。
