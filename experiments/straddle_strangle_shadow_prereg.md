## 1. 动机与证据等级

用户（2026-10-21）：想让系统「根据每个标的的情况与财报前的溢价数据，判断卖宽跨好还是卖同价跨式」。可检验的最小命题：

> 在账本自己的成交与定仓约定下，**同一事件、同一入场日、同一到期日**，卖 25Δ 宽跨的盈亏与卖 ATM 跨式的盈亏有系统差异。

| 依据 | 等级 | 说明 |
|---|---|---|
| 宽跨盈亏平衡带更宽、权利金更少 | 结构事实 | 不是证据，是几何 |
| 「宽跨对尾部更稳」 | 无 | 账本按权利金定仓：权利金少 ⇒ 张数多（T 09-29：跨式 39 张 / 宽跨 150 张，名义股数 3,900 vs 15,000，约 3.85 倍；v1 此处写 38 张，是对比卡当时用了开仓之后的净值少算了 1 张，修订 2 更正），尾部风险被定仓规则放大回来 |
| 25Δ 腿的可成交性 | 弱 | 同一份收盘后快照里 25Δ 腿点差常 > 15%（T put 93.75%）；`earnings_vol_signal` 文件头记过 COST 25Δ 盘后 27.6% vs 盘中 9.6% |
| 单只票的历史尾部频率 | 弱 | 每票 ≤ 8 次财报，「带外 k/8」的 95% 区间约 7%–59%（T，k = 2） |

所以**不预设方向**，检验是双侧的；「选择规则」不在本协议内（§9）。

## 2. 记录什么（只记录，不进任何判断）

三处挂接点，**都只写、从不被开 / 平仓判断读**（§10 的守卫钉住）：

1. **信号行 `strangle_quote`**（`earnings_vol_signal._scan_with_info` 在 `compute_signal` 返回**之后**挂上，同 `gex_ctx` / `shadow_event`）：
   当日快照 `quote_set.contracts` 的 `c25` / `p25`（delta 最接近 ±0.25，**与跨式同一到期日**）的 `symbol / strike / expiry / bid / ask / mid /
   spread_pct / delta / oi / quote_ok`，快照时刻与时段（`fetched_at` / `market_open`）、标的价，以及**点时点**的历史财报涨跌
   （只取财报日早于信号日的）。取不到 ⇒ `available=False` + 原因，腿一律 None，不填 0。
2. **持仓 `shadow_strangle`**（`options_paper_leg._attach_shadow_entry`，账本真正开仓的那一刻）：抄信号行的 25Δ 两腿；
   `status` ∈ `ok`（两腿都能按账本约定成交）/ `unquotable`（不能；**不往后找别的行权价顶替**）/ `no_signal_record`（信号行没带
   `strangle_quote`，如部署当天先于新代码落盘的信号）/ `no_size`（账本定仓给不出张数）；假想入场权利金（空头 = 两腿 bid 之和，多头 = 两腿 ask 之和）；
   **按账本自己的 `size_contracts` 与当时的 `nav_for_sizing` 算出的假想张数**（并记下用的 NAV）；入场时点特征（`features`：跨式 / 宽跨各自的
   权利金、到期盈亏平衡带相对现价的位置、历史涨跌落在带外的次数 k/n、最大腿点差、权利金比、历史涨跌原始列表）。
3. **平仓记录 `shadow_strangle.exit`**（`options_paper_leg._attach_shadow_exit`，跨式在账本里平仓的**同一天**）：
   - 账本这次是 `cboe_mid` 平仓 ⇒ 对影子两个符号**再报价一次**（用账本同一个 `quotes_fn`），空头按 **ask** 买回、多头按 **bid** 卖出（账本的出场约定）；
   - 账本是 `intrinsic`（到期那场的收盘 S）⇒ 影子两腿同样按 S 的内在价值结算；
   - 其他（核销等）⇒ `unpriced`；
   - 任一腿拿不到合格的价 ⇒ `unpriced`（`exit.reason` 说是哪条腿），**不用内在价值顶替**（见下「相对 v0 草案的实现层调整」）；
   - `exit.pnl_usd` = (入场权利金 − 平仓权利金) × 100 × 假想张数（空头；多头取反）。

失败处理：三处任何一步抛了，账本照开照平、照记账；失败在源头登记（`straddle_strangle_shadow.note` → `stats()` →
`scan_timing.counters()["strangle_shadow"]` → alert_manager **P2**）。登记的是**故障**（`signal_error / entry_error / exit_error`）；
不可成交、没有信号记录、平仓无价是**数据**，如实计数、不报警。

### 相对 v0 草案的实现层调整（登记前，零数据，已向用户披露）

- v0 §2 写「某腿没有 ask ⇒ 该腿取平仓日标的价下的内在价值」。实现时发现账本的 `cboe_mid` 平仓路径手上**没有平仓日的标的价**
  （`exit_underlying` 为 None），要拿就得多一次取数或用期权平价估，都不是账本自己的约定。改为 `unpriced`：该单位不进检验，
  数量在进度里单列（`exit_unpriced`）。25Δ 腿没有 ask（没有卖盘）在真实数据里极少见；这一类排除与结果无关的前提是「没有 ask」
  不随涨跌方向系统性出现——**无法事前证明，故如实计数、检验后若占比不小再另议**。
- 新增两个 v0 没写的入场状态：`no_signal_record`、`no_size`（见上），都只计数、不进检验。

## 3. 假设与统计量

- 配对单位 = 一笔**空头**跨式及其影子宽跨（多头单位只描述、不检验——用户关心的是卖方）。
- 度量：`d_i = (宽跨_pnl_usd − 跨式_pnl_usd) ÷ nav_for_sizing_i`（各自按账本定仓规则的张数；`nav_for_sizing` = 入场时账本定仓用的 NAV，
  记在影子记录里）。即「账本若改交易宽跨，这一笔会多赚 / 少赚多少 NAV」。**含定仓杠杆**——这是刻意的，它正是切换时会发生的事。
- 统计量：`D = mean(d_i)`。H0：`d_i` 的分布关于 0 对称（结构不造成系统差异）。H1（双侧）：`D ≠ 0`。

## 4. 独立单位、过滤与排除（全部事前可知，不看结果）

单位 = 每笔平仓。`units()` 给每笔一个 `status`，**只有 `ok` 进检验**；其余各有名字、进度里分开计数：

| status | 含义 |
|---|---|
| `before_start` | 入场日早于 `start_date`（§0：登记前入场） |
| `no_record` | 登记后入场但没有影子记录字段（记录失败 / 旧代码开的仓） |
| `schema:N` | 影子记录的结构版本不是 1 |
| `long_side` | 多头（只描述） |
| `entry_unquotable` / `entry_no_signal_record` / `entry_no_size` | 入场时宽跨不可成交 / 信号行没带记录 / 定仓给不出张数 |
| `exit_unpriced` / `exit_error` / `exit_missing` | 平仓日宽跨无价 / 平仓记录出错 / 平仓记录里没有影子平仓项 |
| `unusable` | 盈亏或 NAV 缺 / 财报日或平仓日缺 / 财报日解析不了 |
| `exit_before_event` | **修订 2**：账本平仓日 ≤ 财报日（见下） |
| `ok` | 进检验 |

（v1 表里的 `exit_not_applicable` 在 `units()` 里走不到——入场不是 `ok` 时先落进 `entry_*`，不会再看平仓项——已从表里去掉；
`exit_missing` 是 v1 实现里一直存在、表里漏列的一类。）

**`exit_before_event`（修订 2）**：`earnings_vol_signal` 的合格窗口含等号（`as_of < 财报日 ≤ 到期日 − expiry_buffer`），
账本在 `to_expiry ≤ expiry_buffer_days` 当天就按 `expiry_buffer` 强平。财报日 = 到期日 − 2 且为盘后（AMC，**财报时段未观测，
一律按 AMC 假设**）时，平仓发生在财报当晚的扫描里——公告还没进报价，这一笔的跨式和影子宽跨测到的都是没有事件的纯时间价值，
却会以 `ok` 计入 `n_units` / `mean(d)`。因此：**平仓日 ≤ 财报日的单位一律不进检验**（账本自己的 `post_event` 也是 `as_of > earnings_date`），
单列计数。BMO 的同形单位也被一并排除（保守，宁可少几个单位）。真实数据里这一形状占可交易的 rich / cheap 信号行的约 6%（4/66，二次检查时一次性的普查，**待验证**）。

- 不可成交的比例**单独如实报告**（它本身就是「宽跨在这个账本里做得了多少」的答案），不往后找别的行权价顶替。
- 不用点差闸门筛宽跨腿（账本对 ATM 腿的 15% 闸门只管「要不要开仓」；宽跨的点差已体现在「按 bid 卖、按 ask 买回」里）。
- `written_off`（核销）的单位影子记为 `unpriced`（`ledger_written_off`），不进检验。

## 5. 置换

- 分块 = 财报日所在 ISO 周；**块内所有单位共用一个符号**（同周事件被同一轮行情推着走，单位层面翻符号会低估方差——本仓「横截面池化」教训）。
- 块数 ≤ 16 ⇒ 枚举全部 `2^块数` 种符号：`p = #{|D_perm| ≥ |D_obs|} ÷ 2^块数`（含自身，并列算「≥」，容差 1e-12，保守）；
  块数 > 16 ⇒ 随机 20000 次，`seed = 20261021`：`p = (1 + #{|D_perm| ≥ |D_obs|}) ÷ (1 + 20000)`。
- 实现对拍一个独立的暴力枚举，并有「按单位翻符号会得到更小 p」的反例测试钉住「块是翻符号的单位」。

## 6. α、就绪闸与判定

- 单个检验，双侧，α = 0.05。**只在就绪后跑一次**，不做中期偷看。
- 就绪（同时满足）：进检验的空头单位 ≥ 30、块数 ≥ 8（块数 b 时双侧 p 的下限是 2 ÷ 2^b：b = 8 ⇒ 0.0078 < 0.05）。
  门槛是「置换分布不至于太抖」的启发式，**不是功效计算**；按目前一个季度只有个位数到十几笔空头开仓，**达标可能要半年以上（待验证）**。
  够不着就是如实的「无法检验」，不是放宽闸门的理由。
- 判定：`p ≤ 0.05` ⇒ `reject_h0`，并报 `D` 的符号（`direction`：`strangle_higher` / `straddle_higher`）；否则 `fail_to_reject_h0`——
  **意思是「这个样本量下没看出差异」，不是「两者一样」；现状（卖 ATM 跨式）不变。**

## 7. 盲化（行为规则）

- 代码保证（修订 2 收窄并补齐）：`progress()` 只返回计数（已记录 / 进检验 / 各状态 / 块数 / 就绪与否）；`run_once()` 未就绪时拒绝运行；
  **产品出口**（Alpha Bot 接口、`progress`）和**每日运行的返回值 / `options_paper_leg.py` CLI 回显**都不带任何一笔的影子盈亏
  （`BLINDED_KEYS` 不出现在 `progress` 里；`run_for_date` 返回的平仓记录剥掉 `shadow_strangle`，测试钉住）。
  v1 写的是「没有任何代码路径把同一笔的影子盈亏与跨式盈亏放进同一个返回值」——说过头了：`run_for_date` 的返回值与手动 CLI 当时就带着
  整条平仓记录（二次检查发现，修订 2 修）；落盘的 `closed_trades.jsonl` 与 `units()` 的 `d`（两者之差）按下一条本来就盲不了。
- 信息论上盲不了：影子记录与账本平仓记录都在 `closed_trades.jsonl` 里。**冻结之前从任何出口把某笔的影子宽跨盈亏和它的跨式盈亏拼在一起看 = 偷看 =

- 页面：Alpha Bot 跨式页只显示影子记录进度（计数）；持仓卡与已平仓表**不**显示任何一笔的影子盈亏（测试遍历接口键名钉住）。
  入场时的「跨式 vs 宽跨」对比卡是入场时点的事实（报价、点差、历史），不含结果，照常显示。
- 冻结：`/usr/local/bin/python3 straddle_strangle_shadow.py --run-once`，结果写
  `<数据根>/options_paper_state/straddle_strangle_shadow_result.json`（`PATHS.straddle_strangle_shadow_result`；先写临时文件再 `os.link`，

## 8. 什么算协议变更

改度量、统计量、置换方式（含分块）、α、单位定义、排除规则（含 §0 的 `start_date` 截断）、「宽跨」的取法（25Δ / 同一到期日）、平仓约定

（日期、版本、理由、改动前是否看过结果），把 `PREREG["version"]` 加一，并声明截断（变更前的单位是否还进检验；默认不进）。
修bug（实现与本文不符）不算协议变更，但同样要记修订并说明受影响的行。

## 9. 本协议**不**回答什么（以及选择规则怎么办）

- **不检验任何「按标的选结构」的规则。** 单只票 ≤ 8 次历史、整个检验才几十个单位，特征 × 结果的交互项功效几乎为零；
  在已经看过 T 的情况下现拟一条规则就是拟合个例。§2 的特征快照是为将来留的：若 §6 拒绝 H0，**再另写一份预注册**，
  规则在看任何「特征 × 结果」之前冻结，并如实评估样本够不够。
- 不回答「宽跨本身赚不赚钱」（只比较两个结构）；不回答「更宽的行权价 / 别的 delta」（只取 25Δ 一档）；
  不回答「用等量张数 / 等 vega 比较」——这些作**描述性**旁证（§11），不出 p 值。
- 只覆盖被账本开仓的单位（受 `max_open`、点差闸门、信号标签约束），外推到别的入场方式要小心。

## 10. 实现与守卫（`tests/test_straddle_strangle_shadow.py`，每条都有会红的对照）

- **不影响账本**：有 / 无 `strangle_quote` 两次跑出的开仓、平仓（报价平仓与内在价值平仓）、现金、净值、meta 逐项相同；记录函数抛了 / 影子那次报价抛了，
  账本照开照平、记录标 `error` 并登记；登记前的持仓序列化逐字节不变（空键整键省略）；没有记录的持仓平仓时不多打一次报价。
- **只记录**：全仓只有 `earnings_vol_signal.py` / `options_paper_leg.py` / `straddle_strangle_shadow.py` 提到这两个键；账本里只出现在
  `_attach_shadow_entry` / `_attach_shadow_exit` / 两个 `to_dict`；信号里只出现在 `_scan_with_info`（AST，含往开仓判断里种读取的自证）。
- **失败在源头登记**：`note()` 对未登记的事件种类抛 `KeyError`（拼错不会悄悄记到别处）；`errors` 只数故障；scan_timing 带计数；alert_manager 对
  `errors > 0` 报 P2，对计数缺失记 `checks_skipped`；**修订 2 起**另有「接线整批断了」探针：快照在而 25Δ 两腿缺的标的 ≥ 5 个、且本轮一个都没取到
  （`stats()["wiring_suspect"]`）⇒ P2（单个标的取不到仍是数据）。
- **与账本口径对拍**：入 / 出场成交约定对拍 `options_paper_leg.entry_fills / exit_fills`；定仓张数对拍 `size_contracts`；
  入场点时点特征对拍 Alpha Bot 对比卡（`alphabot/strangle_compare.py`）。
- 变异自检 20 个全杀（成交方向、盈亏符号、点时点、start_date、多头、NAV 归一、按块翻符号、并列、就绪闸、内在价值、故障登记、钩子外抛 / 不调用 / 不登记、
  序列化、planted 读取、报警、计数、信号钩子登记）。

## 11. 描述性旁证（不出 p 值、不参与判定）

按空头 / 多头分开：不可成交比例；`d_i` 的中位数与胜率；每股盈亏占现价 %（不含杠杆）的配对差；等量张数的 USD 配对差；`exit_unpriced` 占比；
按入场时点差、权利金比、带外次数分层的计数（**只数个数，不看盈亏**，直到 §6 冻结之后）。这些在冻结之前**不实现任何读出**。

## 12. 已知局限

- 快照基本是收盘后的报价，25Δ 腿点差系统性偏宽（`earnings_vol_signal` 文件头记过一个样本：COST 盘后 27.6% vs 盘中 9.6%，**单样本，倍数待验证**）；
  影子记录和账本用同一份，所以结构之间可比，但绝对点差成本偏悲观。
  其中约 4%（787 份可用快照里 32 份，二次检查时的普查）其实是 CBOE 在收盘后给出的**盘中生成的陈旧文件**（`underlying_price_source = cboe_stale_intraday`，
  `market_open` 仍为 False，点差更窄）。记录里不单列这个来源（加字段 = 改结构版本，§8），但可按 `(ticker, 入场日)` 回连保留的
  `cache/options_snapshot_<T>_<日>.json` 取 `underlying_price_source` 分层；它影响的是日后的分层描述，不影响配对（同一份报价）。
- 平仓日跨式与宽跨用同一天，但两者的流动性在平仓日未必一样好；某腿无 ask 时记 `unpriced`（§2）。
- 账本按权利金定仓是**这个账本的**规则，不是宽跨的天然属性；换一种定仓（等 vega、等名义）结论可能不同——这正是 §9 把它列为不回答的原因。
- 影子的第二次报价与账本的平仓报价走同一个 CBOE 进程缓存。缓存的新鲜度自 v0.45.123 起按**业务日 vintage** 判（年龄上限 4 小时；只有交易日历不可用时
  才退回 120 秒），收盘后的扫描整轮只抓一次，所以两次通常来自同一份文件；账本与影子都在同一扫描内取，即使不是同一份，量级也是分钟。
- 财报时段（盘前 / 盘后）未观测，两日窗口同 GEX 预注册。
- 同周事件相关，分块只处理「周」这一层。
